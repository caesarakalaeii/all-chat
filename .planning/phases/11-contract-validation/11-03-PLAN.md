Implement testcontainers_suite.go using testify/suite and testcontainers-go:

1. **LifecycleTestSuite struct:**
   ```go
   type LifecycleTestSuite struct {
       suite.Suite

       // Containers
       redisContainer    testcontainers.Container
       postgresContainer testcontainers.Container

       // Clients
       redisClient    *redis.Client
       postgresClient *pgx.Conn

       // Config
       redisHost    string
       postgresHost string
       logger       *zap.Logger
   }
   ```

2. **SetupSuite() - Run once before all tests:**
   - Start Redis container:
     ```go
     redisContainer, err := testcontainers.GenericContainer(ctx, testcontainers.GenericContainerRequest{
         ContainerRequest: testcontainers.ContainerRequest{
             Image:        "redis:7-alpine",
             ExposedPorts: []string{"6379/tcp"},
             WaitingFor:   wait.ForLog("Ready to accept connections"),
         },
         Started: true,
     })
     ```
   - Start PostgreSQL container (for source-manager database):
     ```go
     postgresContainer, err := testcontainers.GenericContainer(ctx, testcontainers.GenericContainerRequest{
         ContainerRequest: testcontainers.ContainerRequest{
             Image:        "postgres:16-alpine",
             ExposedPorts: []string{"5432/tcp"},
             Env: map[string]string{
                 "POSTGRES_DB":       "allchat_test",
                 "POSTGRES_USER":     "test",
                 "POSTGRES_PASSWORD": "test",
             },
             WaitingFor: wait.ForLog("database system is ready to accept connections"),
         },
         Started: true,
     })
     ```
   - Create Redis and PostgreSQL clients
   - Run schema migrations for PostgreSQL (sources, overlays tables)

3. **TearDownSuite() - Run once after all tests:**
   - Terminate Redis container: `s.redisContainer.Terminate(context.Background())`
   - Terminate PostgreSQL container: `s.postgresContainer.Terminate(context.Background())`
   - Close clients

4. **SetupTest() - Run before each test:**
   - Flush Redis database: `s.redisClient.FlushDB(context.Background())`
   - Truncate PostgreSQL tables: `TRUNCATE sources, overlays CASCADE`
   - Reset logger (capture test-specific logs)

5. **Helper methods:**
   - **StartListener(binary string, env map[string]string) (*exec.Cmd, error):**
     - Start listener subprocess (official or innertube)
     - Pass testcontainer Redis/PostgreSQL URLs via env
     - Pipe stdout/stderr to buffer for assertions
     - Return exec.Cmd for lifecycle control

   - **WaitForReady(cmd *exec.Cmd, timeout time.Duration) error:**
     - Poll /health/ready endpoint until 200 OK
     - Timeout after duration (default 10s)

   - **StopListener(cmd *exec.Cmd) error:**
     - Send SIGTERM
     - Wait for graceful shutdown (max 10s)
     - Verify process exited cleanly

**Why testcontainers:** Per research recommendation, provides clean test isolation with automatic cleanup. Prevents shared state issues between tests. Containers start/stop per suite, flush/truncate per test.

Implement connection_test.go for TEST-03 (connection gating):

1. **TestConnectionGating_ActivateDeactivate:**
   - Setup: Insert source record in PostgreSQL (youtube channel, status=inactive)
   - Start InnerTube listener subprocess
   - Verify: Listener started but NOT polling (no Redis messages)
   - Activate source: Update source status to active in database
   - Send activation event via source-manager integration (Redis pub/sub or HTTP endpoint)
   - Verify: Listener starts polling (messages appear in Redis chat:raw stream)
   - Deactivate source: Update source status to inactive
   - Send deactivation event
   - Verify: Listener stops polling (no new messages in Redis)
   - Verify: Existing connections cleaned up gracefully (no goroutine leaks)

2. **TestConnectionGating_CompareWithOfficial:**
   - Run same test with official youtube-listener binary
   - Compare behavior:
     - Time to start polling after activation (should be <5s for both)
     - Time to stop polling after deactivation (should be <5s for both)
     - Resource cleanup (check process memory before/after, verify no leaks)
   - Assert: InnerTube behavior matches official within tolerance

3. **TestConnectionGating_MultipleActivations:**
   - Test activation → deactivation → activation cycle 5 times
   - Verify: Each activation resumes polling correctly
   - Verify: No state leakage between cycles (message counts reset)

4. **TestConnectionGating_ConcurrentSources:**
   - Setup: Insert 3 source records (3 different channels)
   - Start listener
   - Activate all 3 sources simultaneously
   - Verify: Listener polls all 3 streams concurrently
   - Deactivate 1 source
   - Verify: Listener continues polling other 2, stops polling deactivated source
   - Assert: No cross-contamination between sources

**Verification approach:**
- Check Redis XLEN(chat:raw) before/after to verify polling activity
- Parse listener stdout logs for "polling started" and "polling stopped" messages
- Use `/debug/pprof/goroutine` endpoint to verify goroutine cleanup

**Why this coverage:** Connection gating is critical for production efficiency (don't poll inactive streams). Tests prove InnerTube matches official listener's activation/deactivation behavior.

Implement offline_test.go for TEST-04 (offline detection):

1. **TestOfflineDetection_StreamEnds:**
   - Setup: Start listener polling active stream (mock InnerTube API)
   - Serve mock responses: normal chat messages for 30 seconds
   - Simulate stream offline: Return InnerTube response with `"isLive": false` or empty continuation
   - Verify: Listener detects offline within 10 seconds
   - Verify: Listener stops polling and cleans up gracefully
   - Verify: Source status updated to inactive in database
   - Check Redis: No new messages after offline detection
   - Check logs: "stream offline detected" message present

2. **TestOfflineDetection_CompareWithOfficial:**
   - Run same test with official youtube-listener
   - Compare detection time:
     - InnerTube: Time from offline signal to polling stop
     - Official: Time from offline signal to polling stop
   - Assert: Detection times within 10 seconds of each other

3. **TestOfflineDetection_GracefulCleanup:**
   - Verify cleanup after offline detection:
     - Goroutines terminated (check `/debug/pprof/goroutine` before/after)
     - Redis connections closed (check XINFO CONSUMERS)
     - Database connections released (check PostgreSQL pg_stat_activity)
   - Assert: No resource leaks

4. **TestOfflineDetection_Reconnection:**
   - Simulate: Stream offline → stream back online
   - Offline phase: Return `"isLive": false` for 60 seconds
   - Online phase: Return normal messages with `"isLive": true`
   - Verify: Listener does NOT auto-reconnect (requires manual activation)
   - Note: Auto-reconnect is a feature decision (may vary between listeners)

5. **TestOfflineDetection_NetworkTimeout:**
   - Simulate: InnerTube API timeout (no response for 30s)
   - Verify: Listener treats timeout as transient error (not offline)
   - Verify: Listener retries with exponential backoff
   - Contrast with offline: Explicit "isLive": false → immediate stop
