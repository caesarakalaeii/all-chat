User decisions from CONTEXT.md:
- Parallel execution (both listeners connect simultaneously)
- Message matching by content (username+text+timestamp) robust to ID differences
- Separate Kubernetes pods (production-like isolation)
- Redis Streams production path (both publish to Redis, comparator consumes)
- Mismatch artifacts: full JSON, ±5 context messages, timestamps, latency
- Git-style unified diff format for mismatches
- Continuous monitoring with final report after 24 hours (run to completion)
- <0.1% mismatch threshold = both missing messages AND field differences count

Implement test/shared/message_matcher.go with content-based correlation:

1. **MessageFingerprint struct:**
   ```go
   type MessageFingerprint struct {
       Username  string
       Text      string
       Timestamp time.Time // Truncated to 1-second precision
   }

   func (f MessageFingerprint) Hash() string {
       // Create deterministic hash from content
       data := fmt.Sprintf("%s|%s|%d", f.Username, f.Text, f.Timestamp.Unix())
       hash := sha256.Sum256([]byte(data))
       return fmt.Sprintf("%x", hash[:8]) // First 8 bytes for readability
   }
   ```

2. **MatchMessages(official, innertube []*RawChatMessage, timeWindow time.Duration) MatchResult:**
   - Build fingerprint maps for both message lists
   - Use timeWindow for timestamp truncation (default 1 second per user constraint)
   - Compare fingerprints to find:
     - Matched: same fingerprint, compare fields
     - MissingInInnerTube: in official but not innertube
     - MissingInOfficial: in innertube but not official
     - ContentMismatches: same fingerprint but field differences (excluding allowlisted IDs)
   - Return MatchResult struct with counts

3. **MatchResult struct:**
   ```go
   type MatchResult struct {
       Matched              int
       MissingInInnerTube   int
       MissingInOfficial    int
       ContentMismatches    int
       TotalMessages        int
       MismatchRate         float64 // (missing + content_diff) / total
       Mismatches           []MismatchDetail // For artifact generation
   }
   ```

4. **MismatchDetail struct:**
   ```go
   type MismatchDetail struct {
       Type              string // "missing_innertube", "missing_official", "content_diff"
       OfficialMessage   *RawChatMessage
       InnertubeMessage  *RawChatMessage
       FieldDifferences  map[string]FieldDiff
       Timestamp         time.Time
   }

   type FieldDiff struct {
       OfficialValue  interface{}
       InnertubeValue interface{}
   }
   ```

5. **Unit tests (message_matcher_test.go):**
   - TestMessageFingerprint_Hash: Deterministic hash from username+text+timestamp
   - TestMatchMessages_Identical: 100% match rate when messages identical
   - TestMatchMessages_MissingInInnerTube: Detects messages in official but not innertube
   - TestMatchMessages_MissingInOfficial: Detects messages in innertube but not official
   - TestMatchMessages_ContentMismatch: Detects field differences (same fingerprint)
   - TestMatchMessages_TimeWindowTolerance: Messages within 1s window match
   - TestMatchMessages_MismatchRateCalculation: Verify (missing + diff) / total

**Why content-based matching:** User decision requires robustness to ID differences and message reordering. Fingerprinting by username+text+timestamp (truncated) enables correlation without relying on message IDs.

       StartTime             time.Time

3. **Run(ctx context.Context, duration time.Duration) error:**
   - Create Redis consumer groups for both streams (official:chat:raw, innertube:chat:raw)
   - Use XREADGROUP with BLOCK 1000ms to consume messages
   - Process in batches every 10 seconds:
     - Collect messages from both buffers in time window
     - Call message_matcher.MatchMessages()

     - Write mismatches to artifacts (if any)
   - Log progress every 5 minutes: "Processed: 12,543 | Matched: 12,538 | Mismatch Rate: 0.04%"
   - Continue until duration expires (24 hours)
   - Return final ComparisonStats

4. **Error handling:**
   - Handle Redis connection failures with exponential backoff

   - Graceful shutdown on SIGTERM (flush buffers, write partial report)
