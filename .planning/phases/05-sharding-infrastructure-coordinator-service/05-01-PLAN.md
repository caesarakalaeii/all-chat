<feature name="redis-assignment-registry">
  <name>Redis Assignment Registry with O(1) Lookups</name>
  <files>
    services/source-manager/coordination/registry.go
    services/source-manager/coordination/registry_test.go
    services/source-manager/models/assignment.go
  </files>
  <behavior>
    **Input:** source_id, pod_id, timestamp
    **Output:** Assignment stored in Redis, load updated

    **Test cases:**
    1. StoreAssignment(source1, pod1) → GetAssignment(source1) returns pod1
    2. StoreAssignment increments pod load in Sorted Set
    3. GetLeastLoadedPod returns pod with minimum score in shard:load
    4. Version counter increments on each StoreAssignment call
    5. Multiple assignments in pipeline execute atomically
    6. GetAssignment for non-existent source returns redis.Nil error

    **Redis data structures (user constraint: Claude's discretion on exact structure):**
    - `shard:assignment:{source_id}` → Hash `{pod_id, timestamp, version}`
    - `shard:load` → Sorted Set `{pod_id: channel_count}`
    - `shard:version` → Integer counter (global fencing token)

    **Implementation requirements:**
    - Use Redis Pipeline for atomic multi-operation writes
    - Return version number on StoreAssignment for caller verification
    - GetLeastLoadedPod uses ZRANGEBYSCORE with Count:1 (O(log N))
  </behavior>
