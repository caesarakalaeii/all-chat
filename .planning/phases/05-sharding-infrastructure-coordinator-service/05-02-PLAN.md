<task type="auto">
  <name>Task 2: Implement Kubernetes Lease coordinator with reconciliation loop</name>
  <files>
    services/source-manager/coordination/coordinator.go
  </files>
  <action>
    Create `services/source-manager/coordination/coordinator.go` implementing Kubernetes Lease-based coordinator:

    **Structure:**
    ```go
    type Coordinator struct {
        k8sClient   *kubernetes.Clientset
        registry    *AssignmentRegistry
        assigner    *Assigner
        sourceRepo  registry.Repository  // Existing source-manager repository
        redisClient *redis.Client
        logger      *zap.Logger

        reconcileInterval time.Duration
        stopCh            chan struct{}
    }
    ```

    **Core functions:**

    1. `NewCoordinator(...)` - Initialize with dependencies
    2. `Run(ctx context.Context)` - Start leader election loop:
       - Create in-cluster Kubernetes client via `rest.InClusterConfig()`
       - Get POD_NAME and POD_NAMESPACE from environment (downward API)
       - Create `resourcelock.LeaseLock` with:
         * Name: "shard-coordinator"
         * Namespace: from POD_NAMESPACE env var
         * Identity: from POD_NAME env var
       - Configure `leaderelection.LeaderElectionConfig`:
         * LeaseDuration: 30s (per RESEARCH.md Pattern 2)
         * RenewDeadline: 15s
         * RetryPeriod: 5s
         * ReleaseOnCancel: true
       - Set callbacks:
         * OnStartedLeading: Call `c.reconcile(ctx)` in goroutine
         * OnStoppedLeading: Log "Lost leadership" and call `c.Stop()`
         * OnNewLeader: Log new leader identity
       - Call `leaderelection.RunOrDie(ctx, config)`

    3. `reconcile(ctx context.Context)` - Assignment computation loop:
       - Query active sources from sourceRepo (existing source-manager registry)
       - Query active pods from Kubernetes API (list pods with label `app=twitch-listener` OR `app=kick-listener` OR `app=tiktok-listener`)
         * Filter by phase=Running and ready=true
       - Initialize assigner with pod list (from Plan 05-01)
       - For each source:
         * Compute assignment: `podID = assigner.AssignChannel(source.ID)`
         * Store in registry: `registry.StoreAssignment(ctx, source.ID, podID)`
       - Sleep reconcileInterval (default: 30s from user constraint "monitors per-pod load every 30 seconds")
       - Repeat until stopCh closed

    4. `Stop()` - Graceful shutdown:
       - Close stopCh
       - Log "Coordinator stopped"

    **Error handling:**
    - Kubernetes API errors → log and retry after RetryPeriod
    - Redis errors → log and continue (partial assignment acceptable, will retry next cycle)
    - Source query errors → log and skip that source

    **User constraint enforcement:**
    - 15s heartbeat timeout mentioned in CONTEXT.md, but actual heartbeat implementation deferred to Plan 05-03
    - Phase 5 uses channel count only for load (CONTEXT.md: "Phase 5: Channel count only")
    - No rejection/queueing when pods at capacity (CONTEXT.md: "HPA should scale up")

    **Fencing implementation (SHARD-08):**
    - Registry version counter (from Plan 05-01) provides fencing
    - Kubernetes Lease resourceVersion provides automatic fencing (etcd optimistic concurrency)
    - No manual fencing token management required

    Reference: RESEARCH.md Pattern 2 for full Kubernetes Lease example
