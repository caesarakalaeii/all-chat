In allchat-grafana-dashboards.yaml, locate the Overview dashboard InnerTube stat panel (id: 6, around line 100-115).

Change the panel's query and value mappings:

1. Replace the `targets` expr from:
   `listener_connection_status{platform="youtube_innertube"}`
   to:
   `sum(rate(youtube_listener_messages_published_total{service="youtube-listener-innertube-canary"}[5m]))`

2. Replace the `thresholds` steps from:
   `[{"value": 0, "color": "red"}, {"value": 1, "color": "green"}]`
   to:
   `[{"value": null, "color": "red"}, {"value": 0.001, "color": "green"}]`
   (any non-zero rate means connected; null base = red for zero/no-data)

3. Replace the `mappings` from value-type mappings to range-type mappings:
   ```json
   [
     {"type": "range", "options": {"from": 0, "to": 0, "result": {"text": "Disconnected"}}},
     {"type": "range", "options": {"from": 0.001, "to": null, "result": {"text": "Connected"}}}
   ]
   ```

Rationale: youtube-listener-innertube uses a local metrics package (importing shared/metrics causes promauto duplicate registration panic). The local `youtube_listener_messages_published_total` metric is available and non-zero when the service is actively publishing messages. The `service` label filter ensures we only match the innertube canary, not the standard youtube-listener.

IMPORTANT: Only modify the InnerTube panel (id: 6) in the allchat-overview.json section. Do NOT touch any other panels or dashboards in the file.

<task type="auto">
  <name>Task 2: Fix pipeline-stall alert false positive with sum() aggregation</name>
  <files>../caesar-deployment/apps/platform/kube-prometheus-stack/grafana-alerts/allchat-alerts.yaml</files>
  <action>
In allchat-alerts.yaml, locate the pipeline-stall rule (uid: pipeline-stall, around line 382-396).

Change Ref A's expr from:
  `rate(processor_messages_consumed_total[5m])`
to:
  `sum(rate(processor_messages_consumed_total[5m]))`

Rationale: Without sum(), the rate() returns a vector with one series per platform label. The platform="system" series always has rate=0, which triggers the math condition `$A == 0 && $B > 0` as a false positive even when other platforms (twitch, tiktok, youtube) are actively processing messages. Wrapping in sum() collapses all platform series to a single scalar — the total consumption rate across all platforms.

IMPORTANT: Only modify Ref A's expr in the pipeline-stall rule. Do NOT touch Ref B, Ref C, or any other alert rules.
  </action>
