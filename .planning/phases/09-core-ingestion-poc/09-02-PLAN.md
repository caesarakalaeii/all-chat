Create exponential backoff package using github.com/cenkalti/backoff/v4 with user-specified parameters from CONTEXT.md.

1. **Backoff Configuration**:
   - Use `backoff.NewExponentialBackOff()`
   - `InitialInterval = 2 * time.Second` (user decision: start at 2s)
   - `Multiplier = 2.0` (double each retry: 2s → 4s → 8s → 16s → 32s → 60s)
   - `MaxInterval = 60 * time.Second` (user decision: cap at 60s)
   - `MaxElapsedTime = 0` (never stop retrying, infinite backoff)
   - Add jitter automatically (backoff/v4 includes jitter by default)

2. **Backoff Wrapper**:
   ```go
   type Backoff struct {
       policy *backoff.ExponentialBackOff
       logger *zap.Logger
   }

   func NewBackoff(logger *zap.Logger) *Backoff
   func (b *Backoff) Wait(ctx context.Context, err error) error
   func (b *Backoff) Reset()
   ```

3. **Wait Logic**:
   - Check if error is transient using `innertube.IsTransientError(err)`
   - If fatal, return immediately (no wait)
   - If transient, call `policy.NextBackOff()` to get wait duration
   - Log backoff duration at WARN level: "Transient error, backing off" with error and duration
   - Sleep using `time.After()` with context cancellation support
   - If context cancelled during sleep, return `ctx.Err()`

4. **Reset Logic**:
   - Call `policy.Reset()` after successful operation
   - Resets backoff to initial 2s interval
   - Log at DEBUG level: "Backoff reset after successful operation"

**Implementation reference**: Research RESEARCH.md section "Code Examples > Exponential Backoff with Jitter" lines 514-566

**Critical constraint**: User decision requires fixed backoff parameters (2s initial, 60s max). Do NOT make these configurable via environment variables in PoC phase.

Build continuation-based polling loop with stream state tracking and graceful shutdown.

1. **Stream State Types** (state.go):
   ```go
   type StreamState string
   const (
       StateActive  StreamState = "active"   // Polling normally
       StateFailed  StreamState = "failed"   // Fatal error, stopped
       StateOffline StreamState = "offline"  // Stream ended
   )

   type State struct {
       Current       StreamState
       LastError     error
       LastPollTime  time.Time
       mu            sync.RWMutex
   }
   ```

2. **Poller Structure** (poller.go):
   ```go
   type Poller struct {
       client        *innertube.Client
       parser        *innertube.Parser
       continuation  string
       interval      time.Duration  // Fixed 2s per user decision
       backoff       *Backoff
       state         *State
       logger        *zap.Logger
       logLevel      string  // "debug" or "info" from env var

       // Graceful shutdown
       ctx           context.Context
       cancel        context.CancelFunc
       wg            sync.WaitGroup
   }

   func NewPoller(client *innertube.Client, parser *innertube.Parser, initialContinuation string, logger *zap.Logger) *Poller
   func (p *Poller) Start(ctx context.Context) error
   func (p *Poller) Stop()
   func (p *Poller) GetState() StreamState
   ```

3. **Polling Loop Logic**:
   - Fixed interval ticker: `time.NewTicker(p.interval)` where `p.interval = 2 * time.Second`
   - On each tick:
     a. Check context cancellation (graceful shutdown)
     b. Call `client.GetLiveChatReplay(ctx, p.continuation)`
     c. Parse response using `parser.ParseMessages(resp.Actions, channelID)`
     d. Update continuation token: `p.continuation = resp.Continuation`
     e. Return parsed messages to caller (will be published to Redis in Plan 03)

4. **Error Handling**:
   - Classify error using `innertube.IsTransientError(err)` and `innertube.IsFatalError(err)`
   - **Transient error**:
     - Call `backoff.Wait(ctx, err)` (exponential backoff)
     - Continue polling after backoff completes
     - Log at WARN level (not DEBUG, per user decision: log errors after retries)
   - **Fatal error**:
     - Set state to `StateFailed` or `StateOffline` (depending on error type)
     - Stop polling immediately (do NOT crash the service)
     - Log at ERROR level with error details
     - Return error to caller (service stays alive, per user decision)
   - **Success**:
     - Reset backoff: `backoff.Reset()`
     - Set state to `StateActive`
     - Update `LastPollTime`

5. **Configurable Logging**:
   - Read log level from constructor parameter (passed from main.go in Plan 03)
   - **Debug mode** (`logLevel == "debug"`):
     - Log every poll attempt with continuation token (first 20 chars)
     - Log every message parsed
   - **Default mode** (`logLevel == "info"`):
     - Only log errors after backoff retries exhausted
     - Only log state changes (active → failed)

6. **Graceful Shutdown**:
   - `Start()` runs polling loop in goroutine, increments `wg`
   - `Stop()` calls `cancel()` to signal context, waits on `wg.Wait()`
   - Polling loop checks `ctx.Done()` on every iteration
   - Clean up: close ticker, log "Poller stopped gracefully"

**Implementation reference**: Research RESEARCH.md section "Architecture Patterns > Pattern 1: Continuation-Based Polling Loop" lines 132-168

**Critical constraints**:
- Fixed 1-2s interval (user decision, NOT adaptive)
- Stay alive on fatal errors (user decision: prepares for Phase 10 multi-stream support)
- Configurable log levels (user decision: debug mode for PoC troubleshooting)

**User decision violation check**: Do NOT implement adaptive polling based on `pollingIntervalMillis` from InnerTube response (user explicitly rejected this).
