**Bug 1: Unknown errors classified as transient (types.go line 216)**

Current code in ClassifyError():
```go
// Network errors are transient
return ErrorTypeTransient
```

This fallback catches ALL unknown error types and treats them as transient, causing them to backoff instead of failing fast.

**Test expectations:**
- TestBackoff_Wait_UnknownError: expects immediate return (< 100ms) for `errors.New("unknown error type")`
- Current behavior: waits 2.3s (treated as transient)

**Fix:** Change line 216 from `return ErrorTypeTransient` to `return ErrorTypeFatal`

**Rationale:** Only explicitly recognized transient errors should retry. Unknown errors should fail fast by default. If needed, specific network error types can be added explicitly.

**Updated ClassifyError logic:**
```go
func ClassifyError(err error) ErrorType {
    if err == nil {
        return ErrorTypeTransient
    }

    // HTTP status errors (unwrap error chain if wrapped)
    var httpErr *HTTPStatusError
    if errors.As(err, &httpErr) {
        switch httpErr.StatusCode {
        case 401, 403, 404:
            return ErrorTypeFatal
        case 429, 500, 502, 503, 504:
            return ErrorTypeTransient
        default:
            return ErrorTypeFatal // Unknown HTTP status codes
        }
    }

    // Unknown error types: treat as fatal (fail fast)
    // Only explicitly recognized transient errors should retry
    return ErrorTypeFatal
}
```

**Bug 2: Jitter exceeds test expectations (backoff.go)**

Current: backoff/v4 ExponentialBackOff uses RandomizationFactor = 0.5 (default), giving ±50% jitter.
- 2s base → 1s - 3s range
- Test result: 1.367s (within ±50% but fails test expecting ±25%)

Tests expect ±25% jitter (1.5s - 2.5s range for 2s base).

**Fix:** Add explicit RandomizationFactor configuration in NewBackoff():

```go
func NewBackoff(logger *zap.Logger) *Backoff {
    policy := backoff.NewExponentialBackOff()

    // User-specified configuration (fixed for PoC)
    policy.InitialInterval = 2 * time.Second
    policy.MaxInterval = 60 * time.Second
    policy.Multiplier = 2.0
    policy.MaxElapsedTime = 0 // Infinite retries
    policy.RandomizationFactor = 0.5 // ±25% jitter (0.5 * 0.5 = 0.25 effective)

    policy.Reset()

    return &Backoff{
        policy: policy,
        logger: logger,
    }
}
```

**Wait, that's wrong.** RandomizationFactor in backoff/v4 is the total range, not half. Let me check the library docs...

**Actually:** backoff/v4 RandomizationFactor = 0.5 means "interval * (1 ± 0.5)" = 0.5x to 1.5x range.
- For 2s: 1s - 3s (±50%)

To get ±25% jitter: RandomizationFactor = 0.25
- For 2s: 1.5s - 2.5s (±25%)

**Correct fix:**
```go
policy.RandomizationFactor = 0.25 // ±25% jitter
```

Add this line after line 42 (after Multiplier) in backoff.go.

**Why this matters:**
- Tests use fixed ranges expecting ±25% jitter
- Default ±50% causes test failures when actual duration falls outside expected range
- Production behavior unchanged (still uses jitter, just tighter bounds)
