## Spacing Scale

All spacing uses the existing token set declared in `globals.css @theme`. This phase uses a subset:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`--spacing-1`) | Badge gap, inline icon spacing |
| sm | 8px (`--spacing-2`) | Toggle-label gap, compact element spacing |
| md | 16px (`--spacing-4`) | Default element spacing, card internal padding |
| lg | 24px (`--spacing-6`) | Section separation within a card |
| xl | 32px (`--spacing-8`) | Page-level vertical rhythm |
| 2xl | 48px (`--spacing-12`) | Major section breaks |
| 3xl | 64px (`--spacing-16`) | Page-level spacing |

Exceptions: Toggle touch target minimum 44px height (accessibility — WCAG 2.5.5 target size). Achieved via `min-h-[44px]` on the toggle row, not by changing the spacing scale.

## Color

All values from `globals.css @theme` semantic tokens. No new colors introduced.

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `--color-bg` | `oklch(0.09 0.007 270)` ≈ `#07070a` | Page background, main surface |
| Secondary (30%) | `--color-surface` / `--color-surface-2` | `oklch(0.11…)` / `oklch(0.14…)` | Card backgrounds, toggle row hover state |
| Accent (10%) | `--color-twitch` (`#a37bff`) | `#a37bff` | Active nav underline gradient only |
| Destructive | `--color-destructive` (shadcn semantic) | inherited from base-nova | No destructive actions in this phase (see Copywriting) |

Accent reserved for: active nav tab underline gradient (`after:bg-linear-to-r after:from-twitch after:to-tiktok`) only. NOT used on toggle switches, badges, or status indicators in this page.

Feature gate status uses semantic amber (premium locked) and green (free for all) — these follow the existing admin page badge pattern already established in `users/page.tsx`:
- Premium-locked gate badge: `bg-amber-500/10 text-amber-400 border-amber-500/20` (matches existing PREMIUM badge)
- Free-for-all gate badge: `bg-green-500/10 text-green-400 border-green-500/20` (new, consistent with amber pattern)

## Page Layout

Route: `/admin/features`

Layout inherits `admin/layout.tsx` — sticky `AdminNav` at top, `ToastProvider`, `ProtectedRoute requireAdmin`.

Page structure (single column, max-w-3xl centered):

```
Page header
  h1: "Features"  [text-2xl font-bold text-text]
  p:  "Manage capability-level premium gates. Toggle a feature free to grant access to all users without a code deploy."  [text-sm text-text-sub]

Gate list (Card)
  Card header: "Feature Gates ({count})"  [text-base font-bold]
  For each gate row:
    - Feature key  [font-mono text-sm text-text]
    - Description  [text-sm text-text-sub]
    - Status badge  [amber = premium-only / green = free for all]
    - Toggle button  [see toggle spec below]
  Dividers: border-b border-border between rows
```

Column widths (single Card, no split panel — this page has few enough items):
- Feature key + description: flex-1
- Status badge: flex-shrink-0
- Toggle: flex-shrink-0, 44px touch target

## Interaction States

### Toggle Switch States

| State | Visual | Behavior |
|-------|--------|----------|
| Premium (is_premium=true) | Amber pill, thumb right, badge "Premium only" | Click → show Dialog confirmation before switching to free |
| Free (is_premium=false) | Green pill, thumb left, badge "Free for all" | Click → show Dialog confirmation before switching to premium |
| Loading | Opacity 50%, disabled, `cursor-not-allowed` | During PATCH request in flight |
| Error | Toast "Failed to update feature gate. Please try again." | On non-2xx response |

### Dialog Confirmation

Use Dialog for both directions (premium→free AND free→premium). Feature gates affect access for all users — both directions need confirmation.

| Direction | Dialog Title | Description | Confirm button | Cancel button |
|-----------|-------------|-------------|----------------|---------------|
| Premium → Free | "Make sharing free for all users?" | "All authenticated users will gain access to this feature immediately. No code deploy required." | "Make Free" | "No, keep as-is" |
| Free → Premium | "Restrict sharing to premium users?" | "Only users with premium access will be able to use this feature." | "Make Premium" | "No, keep as-is" |

Dialog confirm uses default variant (NOT destructive — making a feature free or premium is the intended lifecycle action). Dialog cancel uses outline variant.
