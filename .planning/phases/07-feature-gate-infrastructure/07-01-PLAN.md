    1. Create `docs/adr/0008-feature-gate-infrastructure.md` following the format of ADR-0007:
       - **Title:** ADR-0008: Feature Gate Infrastructure
       - **Status:** Accepted
       - **Date:** 2026-03-29
       - **Context:** All-Chat needs the ability to ship experimental features as premium-only, let the community test them, and flip them to free at any time without code deploys. Currently `users.is_premium` is checked directly in middleware — adding a new gated feature requires code changes and a deploy.
       - **Decision:** Implement a `feature_gates` Postgres table as the source of truth with an in-memory cache per service (refreshed via Redis Pub/Sub + 60s TTL fallback). The `RequirePremium` middleware is rewritten to check the gate before the user premium status. An admin UI at `/admin/features` provides toggle switches.
       - **Alternatives considered:**
         (a) Environment variable toggles — simple but requires pod restart to change
         (b) Per-user feature flags (LaunchDarkly style) — overkill, adds external dependency
         (c) Hardcoded constants in code — requires deploy for every change
       - **Consequences:** Feature lifecycle becomes "ship premium, graduate to free" with zero-downtime toggles. Each service needs to boot a FeatureGateCache. Unknown gate keys default to premium (safe). Only share-service consumes it today; cache lives in share-service, not shared/, to avoid premature abstraction.

    2. Add entry to `docs/adr/README.md`:
       - `| ADR-0008 | Feature Gate Infrastructure | Accepted | DB + in-memory cache for capability-level premium toggling |`
