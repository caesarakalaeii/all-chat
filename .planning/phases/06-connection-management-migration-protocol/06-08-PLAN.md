**Root Cause (from UAT.md):** Readiness probe at line 85 of health.go compares active_channels (5) against raw assignmentCount (17) instead of filtered count. Coordinator assigns 17 source IDs, but after database filtering in SyncChannels(), only 5 channels actually exist. GetAssignmentCount() returns len(assignedSourceIDs) which includes all coordinator assignments, but only 5/17 have corresponding database channels.

**Fix in services/twitch-listener/channels/manager.go:**

1. Add `filteredAssignmentCount int` field to Manager struct (below assignedSourceIDs field)

2. In SyncChannels() method, the filtering logic at line 258 sets `desiredChannels = assignedChannels` BEFORE acquiring m.mu.Lock() at line 261. To track the filtered count safely:

   Store `len(assignedChannels)` in a local variable before line 261:
   ```go
   desiredChannels = assignedChannels
   filteredCount := len(assignedChannels)  // Capture before lock
   ```

   Then AFTER line 261 (after acquiring lock), update the field:
   ```go
   m.mu.Lock()
   defer m.mu.Unlock()

   // Store filtered count for readiness probe
   m.filteredAssignmentCount = filteredCount
   ```

3. Add GetFilteredAssignmentCount() method:
   ```go
   // GetFilteredAssignmentCount returns the number of assigned sources that have database channels
   // Used by readiness probe to check if all filtered assigned channels are active
   func (m *Manager) GetFilteredAssignmentCount() int {
       m.mu.RLock()
       defer m.mu.RUnlock()
       return m.filteredAssignmentCount
   }
   ```

**Fix in services/twitch-listener/handlers/health.go:**

Change line 85 from:
```go
if activeChannelCount < assignmentCount {
```

To:
```go
filteredAssignmentCount := h.chanMgr.GetFilteredAssignmentCount()
if activeChannelCount < filteredAssignmentCount {
```

Update checks map line 90 to show filtered count:
```go
checks["expected"] = filteredAssignmentCount
```

**Why this works:** Readiness probe now compares active_channels (5) against filtered assignments (5) instead of raw assignments (17). When coordinator assigns 17 source IDs but only 5 have database channels, pod correctly reports ready after connecting to those 5 channels.

**Thread safety:** Capture len(assignedChannels) before acquiring lock, then update m.filteredAssignmentCount after acquiring lock. GetFilteredAssignmentCount() uses RLock for safe concurrent reads.
