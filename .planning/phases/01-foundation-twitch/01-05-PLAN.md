<task type="checkpoint:human-verify" gate="blocking">
  <what-built>
Complete message deletion infrastructure with Twitch integration:
- Message ID Registry (Redis hash with 1-hour TTL)
- Twitch IRC deletion event capture (CLEARMSG, CLEARCHAT)
- Message processor deletion handling (buffer, normalize, publish)
- Frontend deletion event processing (WebSocket, state filtering)
  </what-built>
  <how-to-verify>
**Prerequisites:**
1. Start all services: `make docker-up` (includes postgres, redis, all services)
2. Verify services healthy: Check `/health/ready` endpoints return 200
3. Create test overlay: Use admin UI or API to create overlay with Twitch source
4. Open overlay in browser: `http://localhost:3000/overlay/{overlay_id}`

**Test Case 1: Single Message Deletion (<500ms latency)**
1. Join test Twitch channel as moderator
2. Send test message: "This will be deleted"
3. Observe message appears in overlay
4. Delete message using Twitch mod tools (right-click message → Delete)
5. **Expected:** Message disappears from overlay within 500ms
6. Check browser console: Should show `[Deletion] single` log entry
7. Check message-processor logs: Should show "Applying buffered deletion" or direct deletion

**Test Case 2: User Timeout (Batch Deletion)**
1. Send multiple messages as test user (3-5 messages)
2. Observe all messages appear in overlay
3. Timeout user for 10 minutes: `/timeout testuser 600`
4. **Expected:** All user's messages disappear simultaneously (single state update)
5. Check browser console: Should show `[Deletion] batch` with target_user_id
6. Verify no individual message deletions (efficient batch removal)

**Test Case 3: Full Chat Clear**
1. Populate overlay with messages from multiple users (5-10 messages)
2. Execute full chat clear: `/clear` in Twitch chat
3. **Expected:** All messages disappear from overlay instantly
4. Check browser console: Should show `[Deletion] clear`
5. Verify overlay shows empty state (no messages)

**Test Case 4: Race Condition (Deletion Before Message)**
This is hard to test manually but verify buffer metrics:
1. Check Redis: `redis-cli KEYS msgid:deletion_buffer:*` (should be empty or have expired entries)
2. Check message-processor metrics: `curl localhost:8087/metrics | grep deletion`
3. Look for `deletions_buffered` and `buffered_deletions_applied` counters
4. If any buffered deletions occurred, verify they were applied when message arrived

**Performance Verification:**
1. Measure latency: Time from deletion action to message disappearing
2. Target: <500ms for single deletion (CLEARMSG has minimal IRC lag)
3. Batch deletion should feel instant (single UI update)
4. Full clear should be instantaneous (empty array assignment)

**Debugging:**
- Twitch Listener logs: `docker logs -f allchat-twitch-listener`
- Message Processor logs: `docker logs -f allchat-message-processor`
- API Gateway logs: `docker logs -f allchat-api-gateway`
- Redis Streams: `redis-cli XREAD COUNT 10 STREAMS chat:raw-messages 0`
- Redis Pub/Sub: `redis-cli PSUBSCRIBE overlay:*`
- Message ID Registry: `redis-cli HGETALL msgid:registry:twitch:{channel_name}`
  </how-to-verify>
