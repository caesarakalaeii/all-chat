Create `coordination_lock.go`:

**CoordinationLock struct:**
- redisClient (*redis.Client)
- lockKey (string) - "rebalancing:coordination_lock"
- lockValue (string) - Unique identifier for this operation (e.g., "rebalancing-{timestamp}")
- lockTTL (time.Duration) - 60 seconds
- logger (*zap.Logger)

**NewCoordinationLock(redisClient *redis.Client, logger *zap.Logger) *CoordinationLock:**
- Initialize with default lockKey and lockTTL
- Return lock instance

**AcquireLock(ctx context.Context, operation string) (bool, error):**
- Generate unique lockValue: "{operation}-{timestamp}"
- Redis SET NX EX command per RESEARCH.md Pattern 5:
  - result, err := redisClient.SetNX(ctx, lockKey, lockValue, lockTTL).Result()
- If result == true:
  - Log: "Acquired coordination lock" operation={operation}
  - Return true, nil
- If result == false:
  - Query current lock holder: holder, _ := redisClient.Get(ctx, lockKey).Result()
  - Log: "Lock held by another operation" holder={holder}
  - Return false, nil
- Return error if Redis fails

**ReleaseLock(ctx context.Context) error:**
- Use Lua script for atomic check-and-delete per RESEARCH.md:
  ```lua
  if redis.call("get", KEYS[1]) == ARGV[1] then
      return redis.call("del", KEYS[1])
  else
      return 0
  end
  ```
- Execute: result, err := redisClient.Eval(ctx, script, []string{lockKey}, lockValue).Result()
- If result == 1: Log "Released coordination lock"
- If result == 0: Log "Lock not owned by this operation (already expired or taken)"
- Return error

**ExtendLock(ctx context.Context) error:**
- Use Lua script for atomic check-and-expire:
  ```lua
  if redis.call("get", KEYS[1]) == ARGV[1] then
      return redis.call("pexpire", KEYS[1], ARGV[2])
  else
      return 0
  end
  ```
- Execute: result, err := redisClient.Eval(ctx, script, []string{lockKey}, lockValue, lockTTL.Milliseconds()).Result()
- If result == 0: Return error "lock no longer owned by this operation"
- Log debug: "Extended coordination lock"
- Return nil

- TestAcquireLock_Success: Verify lock acquired, returns true
- TestAcquireLock_AlreadyHeld: Second acquire returns false, first holder unchanged
- TestReleaseLock_Success: Verify lock released, subsequent acquire succeeds
- TestReleaseLock_WrongOwner: Lock held by different operation, release fails
- TestExtendLock_Success: TTL extended from 10s to 60s
- TestExtendLock_Expired: Lock expired before extension, returns error

Use miniredis for Redis mocking.

if report.ShouldRebalance {
    // Check cooldown first
    allowed, reason, err := c.throttler.CheckCooldown(ctx, report.ImbalanceRatio)
    if err != nil || !allowed {
        c.logger.Info("Rebalancing skipped", zap.String("reason", reason))
        return nil
    }

    // Try to acquire coordination lock
    lock := NewCoordinationLock(c.redisClient, c.logger)
    acquired, err := lock.AcquireLock(ctx, "rebalancing")
    if err != nil {
        c.logger.Error("Lock acquisition failed", zap.Error(err))
        return fmt.Errorf("lock acquisition failed: %w", err)
    }
    if !acquired {
        c.logger.Info("Rebalancing skipped - coordination lock held (likely HPA scale event)")
        return nil
    }
    defer lock.ReleaseLock(ctx)

    // Execute rebalancing with lock held
    c.logger.Info("Load imbalance detected, planning rebalancing (lock acquired)")

    plans, err := c.rebalancer.PlanRebalancing(ctx, loads, report.AvgLoad, c.incompleteRebalancingAttempts)

**Context per CONTEXT.md:** "Staggered pod startup: each new pod waits random delay (0-30s) before querying coordinator (prevents thundering herd)"

**Rationale per RESEARCH.md Pattern 5:**
- HPA scale-up creates multiple pods simultaneously (e.g., 2 → 10 pods)
- All pods querying coordinator at once causes Redis connection spike, CPU spike
- 0-30s jitter spreads requests across 30-second window
- Research: Netflix, Facebook, AWS all use jitter for distributed startup coordination
