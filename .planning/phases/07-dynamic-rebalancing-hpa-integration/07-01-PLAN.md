- Unit tests validating load calculations and threshold logic

Create `services/source-manager/coordination/load_monitor.go`:

**LoadMonitor struct:**
- redisClient (*redis.Client) - Query channel counts from assignment registry
- prometheusURL (string) - Prometheus endpoint for message rate queries
- httpClient (*http.Client) - HTTP client for Prometheus API calls
- metrics (*metrics.ShardMetrics) - Metrics recorder
- logger (*zap.Logger)

**PodLoad struct:**
- PodID (string)
- ChannelCount (int)
- MessageRate (float64) - messages/sec from Prometheus
- LoadScore (float64) - composite weighted score

**CalculateLoadScore(channelCount int, messageRate float64) float64:**
- Per CONTEXT.md: Use weighted combination of message rate AND channel count
- Initial weights per RESEARCH.md Pattern 1: messageRateWeight=0.7, channelCountWeight=0.3
- Return: (messageRate * 0.7) + (float64(channelCount) * 0.3)
- Rationale: Message processing dominates CPU (research guidance), connection overhead is secondary

**MonitorPodLoads(ctx context.Context, podIDs []string) ([]PodLoad, error):**
- For each podID:
  - Query channel count from Redis assignment registry (O(1) via ZCOUNT on shard:load sorted set)
  - Query message rate from Prometheus: `rate(listener_messages_received_total{pod=~"podID.*"}[30s])`
  - If Prometheus query fails or returns 0, log warning and default messageRate=0 (graceful degradation)
  - Calculate loadScore = CalculateLoadScore(channelCount, messageRate)
  - Append to []PodLoad
- Return populated PodLoad array
- Error handling: Log individual pod failures, continue processing remaining pods

**getChannelCount(ctx context.Context, podID string) (int, error):**
- Query Redis Sorted Set `shard:load` via ZCOUNT (Phase 5 infrastructure)
- Return channel count for podID
- Error: Return 0 if podID not found (new pod with no assignments yet)

**getMessageRate(ctx context.Context, podID string) (float64, error):**
- Build PromQL query: `rate(listener_messages_received_total{pod=~"%s.*"}[30s])` (30s window per requirements)
- HTTP GET to Prometheus /api/v1/query endpoint
- Parse JSON response, sum all sample values (aggregate across channels)
- Return total message rate for pod
- Error handling: Return 0.0 on network errors (Prometheus unavailable), don't block monitoring

Add to `load_monitor.go`:

**ImbalanceReport struct:**
- MaxLoad (float64) - Highest pod load score
- MinLoad (float64) - Lowest pod load score
- AvgLoad (float64) - Average load across all pods
- ImbalanceRatio (float64) - max_load / avg_load (standard formula)
- MaxMessageRate (float64) - Highest message rate among all pods
- OverloadedPods ([]string) - Pod IDs with load > avgLoad
- UnderutilizedPods ([]string) - Pod IDs with load < avgLoad
- ShouldRebalance (bool) - Trigger decision result
- Reason (string) - Explanation for trigger decision

**CalculateImbalance(loads []PodLoad) ImbalanceReport:**
- Calculate max, min, avg load scores
- Calculate max message rate across all pods
- Calculate imbalanceRatio = maxLoad / avgLoad (handle avgLoad=0 edge case)
- Identify overloaded pods (load > avgLoad) and underutilized pods (load < avgLoad)
- **Dual-condition gating** per CONTEXT.md:
  - ShouldRebalance = true IF (imbalanceRatio > 0.5 AND maxMessageRate > 100.0)
  - Rationale: "Avoid unnecessary rebalancing when system is mostly idle, but remain responsive under load"
  - If imbalanceRatio <= 0.5: Reason = "imbalance_ratio within threshold"
  - If maxMessageRate <= 100: Reason = "max_msg_rate below threshold (system mostly idle)"
  - If both conditions met: Reason = "imbalance detected (ratio=X, max_rate=Y)"
- Update metrics: metrics.LoadImbalanceRatio.Set(imbalanceRatio), metrics.PodLoadMax.Set(maxLoad), metrics.PodLoadAvg.Set(avgLoad)
- Return ImbalanceReport
