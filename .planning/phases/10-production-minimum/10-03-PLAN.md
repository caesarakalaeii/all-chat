  <action>
Create streams/manager.go matching official youtube-listener pattern:

1. Manager struct:
   - leader *sourcemanager.LeadershipCoordinator (for stream ownership)
   - repository *Repository (from Plan 01)
   - discovery *innertube.Discovery (from Plan 01)
   - publisher *publisher.RedisPublisher (from Phase 9)
   - logger *zap.Logger
   - mu sync.RWMutex
   - activeStreams map[string]*Stream (videoID → stream state)
   - pollers map[string]*poller.Poller (videoID → active poller)
   - discovering map[string]*DiscoveryState (channelID → discovery state)
   - connectedOverlays map[string]time.Time (overlay_id → connection_time)
   - channelConnectedOverlays map[string]map[string]struct{} (channel_id → overlay_ids)
   - redisClient *redis.Client

2. DiscoveryState struct:
   - ChannelID string
   - OverlayID string
   - StartedAt time.Time
   - Attempts int
   - CancelFunc context.CancelFunc

3. Start(ctx) error method:
   - Initialize PostgreSQL LISTEN for source changes (if source-manager integration needed)
   - Start periodic sync from source-manager (every 30s)
   - Return nil (non-blocking)

4. OnOverlayConnected(overlayID, sources []Source) method:
   - For each YouTube source, call startAsyncDiscovery(source.ChannelID, overlayID)
   - Track overlay connection in connectedOverlays and channelConnectedOverlays

5. OnOverlayDisconnected(overlayID) method:
   - Remove overlay from tracking maps
   - For each channel, check if any overlays still connected
   - If no overlays connected, stop poller after debounce delay (5 seconds)

6. startAsyncDiscovery(channelID, overlayID) method:
   - Lock discovering map, check if already discovering
   - Check Redis cache first: repository.GetChannelVideoMapping(ctx, channelID)
   - If cached, start poller immediately with cached video ID
   - If not cached, start background goroutine: go discoveryLoop(ctx, state)

7. discoveryLoop(ctx, state) method:
   - Backoff sequence: [30s, 1m, 2m, 5m, 10m]
   - 15-minute timeout (per user decision)
   - Attempt discovery.DiscoverLiveStream(ctx, channelID)
   - On success: persist to Redis, start poller, return
   - On failure: exponential backoff, retry
   - On timeout: log error, give up

8. startPoller(channelID, videoID, overlayID) method:
   - Claim leadership: leader.ClaimLeadership(ctx, videoID, 60*time.Second)
   - If claimed, create poller and start in goroutine
   - Track in activeStreams and pollers maps

9. Shutdown(ctx) error method:
   - Stop all active pollers
   - Flush Redis buffers
   - Clear Redis state
   - Release leadership locks
   - 25-second timeout (per user decision)

Create manager_test.go:
- TestManager_OnOverlayConnected_CachedVideoID (uses Redis cache)
- TestManager_OnOverlayConnected_Discovery (starts async discovery)
- TestManager_DiscoveryLoop_Success (discovers and starts poller)
- TestManager_DiscoveryLoop_Timeout (gives up after 15 minutes)
- TestManager_OnOverlayDisconnected_StopsPoller (debounced stop)

Use shared/sourcemanager package (already used by official youtube-listener).

Why async discovery: User decision - non-blocking to avoid delaying source-manager notifications. Discovery can take 1-5 seconds, so background goroutine prevents cascading delays.
