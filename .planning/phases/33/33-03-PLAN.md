# Plan 33-03: Inject visual-customizer Cascade Layer into Overlay Embed Page

**Phase:** 33 — CSS Architecture Foundation
**Requirements:** VISM-03
**Status:** Not started

## Goal

Insert the `visual-customizer` layer into the cascade layer declaration in `events.css` (positioned between `marketplace-themes` and `user-overrides`), and wire `visual_settings` into the OBS overlay page so it loads from the public config API and injects the generated CSS into the page via a `<style>` tag.

## Success Criteria

1. `events.css` cascade layer order is: `base, design-system, marketplace-themes, visual-customizer, user-overrides`
2. Overlay embed page (`/overlay/[id]`) loads `visual_settings` from the config API response
3. When `visual_settings` is non-empty, a `<style>` tag with `@layer visual-customizer { :root { ... } }` is rendered in the page
4. When `visual_settings` is empty `{}`, no extra `<style>` tag is emitted (empty string guard in `visualSettingsToCss`)
5. The injected style tag renders after the existing `customCss` style tag so layer ordering is preserved

## Files to Modify

### `frontend/src/styles/events.css`

Change line 11 from:

```css
@layer base, design-system, marketplace-themes, user-overrides;
```

To:

```css
@layer base, design-system, marketplace-themes, visual-customizer, user-overrides;
```

This is the authoritative cascade layer declaration for the overlay embed page context. The `visual-customizer` layer sits above theme defaults and below raw user CSS, exactly matching the architecture in the requirements.

### `frontend/src/app/overlay/[id]/page.tsx`

**1. Add import** (after existing imports, before `'@/styles/events.css'`):

```ts
import { visualSettingsToCss } from '@/lib/utils/visual-settings-to-css'
import type { VisualSettings } from '@/lib/types/visual-settings'
```

**2. Add state** (alongside existing `customCss` state):

```ts
const [visualSettingsCss, setVisualSettingsCss] = useState('')
```

**3. Load from config** — in the `loadConfig` async function, after the line that sets `customCss`:

```ts
if (data.visual_settings && typeof data.visual_settings === 'object') {
  setVisualSettingsCss(visualSettingsToCss(data.visual_settings as Partial<VisualSettings>))
}
```

**Note:** `HandleGetPublicConfig` does not currently expose `visual_settings`. As part of this plan, update the handler to include it:

In `services/overlay-manager/handlers/config.go`, update `HandleGetPublicConfig` response to include `visual_settings`:

```go
c.JSON(http.StatusOK, gin.H{
    "display_settings": config.DisplaySettings,
    "custom_css":       config.CustomCSS,
    "visual_settings":  config.VisualSettings,
    "sources":          sourceStatus,
})
```

**4. Inject style tag** — in the JSX return, after the existing `customCss` style block:

Current structure:
```tsx
{customCss.trim().length > 0 && (
  <style dangerouslySetInnerHTML={{ __html: customCss }} />
)}
```

Add immediately after:
```tsx
{visualSettingsCss.length > 0 && (
  <style dangerouslySetInnerHTML={{ __html: visualSettingsCss }} />
)}
```

The order of the two `<style>` tags matters for cascade correctness:
- `customCss` is in `user-overrides` layer (highest priority)
- `visualSettingsCss` is in `visual-customizer` layer (below user-overrides)

Since `@layer` declarations establish explicit order via the `@layer base, ..., visual-customizer, user-overrides` declaration in `events.css`, the DOM insertion order of these two `<style>` tags does not affect cascade priority — but placing `visualSettingsCss` first and `customCss` second is cleaner and matches the layer order.

Reorder to:
```tsx
{visualSettingsCss.length > 0 && (
  <style dangerouslySetInnerHTML={{ __html: visualSettingsCss }} />
)}
{customCss.trim().length > 0 && (
  <style dangerouslySetInnerHTML={{ __html: customCss }} />
)}
```

## Cascade Layer Architecture Summary

After this plan, the live OBS overlay page has:

```
@layer base           — Tailwind/Next.js base styles
@layer design-system  — All-Chat component tokens
@layer marketplace-themes — Theme CSS from marketplace (unchanged)
@layer visual-customizer  — Generated --chat-* properties from visual_settings JSON (NEW)
@layer user-overrides — Custom CSS from editor (unchanged, highest priority)
```

The `visual-customizer` layer can set any CSS property or custom property. Because it sits above `marketplace-themes`, it overrides theme defaults without needing `!important`. Because it sits below `user-overrides`, raw CSS entered by the user always wins.
