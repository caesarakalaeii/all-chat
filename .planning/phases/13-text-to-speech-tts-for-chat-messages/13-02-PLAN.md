<objective>
Ship the Phase 13 backend: a new `overlay_tts_configs` table + feature_gate row, the `shared/featuregates` + `shared/middleware` moves so overlay-manager can consume them, AES-GCM-encrypted storage of the user's ElevenLabs API key using the existing `shared/encryption` package, per-overlay JWT sign/verify for the OBS-URL `tts_token` scheme, and 7 HTTP endpoints (6 from CONTEXT D-11..D-16 + the 7th `GET /tts-config` from research Open Question 3). The `POST /tts` endpoint streams upstream ElevenLabs audio (`audio/mpeg`) back to the browser with client-disconnect propagation.

Purpose: Establishes the authenticated, encrypted backend for premium ElevenLabs TTS. After this plan, the frontend work in Plans 01 and 03 can read the feature-gate state and call all 7 endpoints. The AES-GCM key storage also closes the CLAUDE.md tech-debt note ("Token encryption is basic (TODO: implement AES-GCM)" — the note is stale; this plan wires the existing `shared/encryption.AESEncryptor` into a second service).

Output: Migration 049 (+ down), moved shared packages, 4 new overlay-manager packages (tts/, repository/tts_config_repo.go, handlers/tts.go, models/tts_config.go), full handler test suite, k8s deployment patched for `TOKEN_ENCRYPTION_KEY`.

Note: downgrading a previously-premium user does NOT revoke their OBS URL's TTS access — the JWT remains valid until the user (or admin) rotates the per-overlay signing secret via the existing rotate-token endpoint. This 'graceful permanence' is an explicit trade-off for streaming-overlay reliability; a premium check on POST /tts would cause OBS audio to cut out the instant premium lapses mid-stream.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OBS browser source → api-gateway → overlay-manager | Unauthenticated bearer (tts_token JWT in URL); overlay-manager re-verifies each request |
| Dashboard (user JWT) → overlay-manager | Authenticated; per-overlay ownership check required |
| overlay-manager → api.elevenlabs.io | Trusted third-party; user's xi-api-key travels only over TLS |
| PostgreSQL (at rest) | overlay_tts_configs.encrypted_api_key is AES-GCM ciphertext; plaintext never persisted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | Information Disclosure | `overlay_tts_configs.encrypted_api_key` column | mitigate | AES-GCM via `shared/encryption.AESEncryptor`. Encrypt in `HandleSaveTTSConfig` before repo write; decrypt only when about to set `xi-api-key` header. Master key from env `TOKEN_ENCRYPTION_KEY` (same K8s secret that auth-service uses). Never log plaintext. |
| T-13-02 | Tampering | JWT verification in `HandleTTS` | mitigate | `jwt.ParseWithClaims` callback asserts `*jwt.SigningMethodHMAC` on `token.Method` and rejects any non-HMAC alg (algorithm confusion defence). Only HS256 accepted. |
| T-13-03 | Spoofing | Leaked `tts_token` reuse | mitigate | D-10 rotation: `HandleRotateToken` generates a fresh 32-byte `tts_signing_secret` via `crypto/rand.Read`; all pre-rotation JWTs fail verification because secret changed. No `exp` claim — rotation IS the revocation. |
| T-13-04 | Denial of Service | `POST /tts` billing abuse (attacker burns quota) | mitigate | In-memory per-overlay rate limit (60 requests/min) inside `TTSHandler`. Rate-limited requests return 429. `Map<overlayID, struct{count int; windowStart time.Time}>` guarded by `sync.Mutex`. Reset on server restart is acceptable. Plus per-overlay tts_token gate. |
| T-13-05 | Information Disclosure | Zap logger leaking api_key | mitigate | Code review rule: never `zap.String("api_key", ...)`, `zap.String("apiKey", ...)`, or `zap.String("xi-api-key", ...)`. Log only `zap.String("overlay_id", id)` and `zap.Error(err)`. Enforced in `<acceptance_criteria>` via `grep -v` check. |
| T-13-06 | Information Disclosure | Public config endpoint leak | mitigate | `HandleGetPublicConfig` (line 217 of main.go) remains UNTOUCHED. Encrypted key lives in `overlay_tts_configs` (separate table), never read by public handler. Regression test: `TestPublicConfigHidesTTSKey` asserts the JSON response never contains `encrypted_api_key`, `tts_signing_secret`, or any TTS-config column. |
| T-13-14 | Tampering | Nonce reuse in AES-GCM | mitigate | `shared/encryption.EncryptString` generates a fresh 12-byte nonce from `crypto/rand.Reader` per call (verified at shared/encryption/encryption.go:77-79). Implementation is reused; executor does NOT write new crypto code. (Renumbered from T-13-07 to avoid collision with Plan 03's T-13-07 "Key leak in browser state".) |
| T-13-08 | Elevation of Privilege | Non-premium user reaches `POST /tts-config` | mitigate | `middleware.RequirePremium(dbPool, gateCache, "tts", log)` applied to all 5 config-mutation endpoints. Tested via `TestSaveTTSConfigRequiresPremium` with a `mockGateChecker{isPremiumResult:true}` + non-premium user → 403. |
| T-13-09 | Information Disclosure | Owner scope on `GET /tts-config` | mitigate | Uses the same `h.overlays.GetByIDAndUserID(ctx, overlayID, userID)` pre-check as `handlers/config.go:58-62`. Different-user access returns 404, never leaks `has_elevenlabs_config`. |
| T-13-10 | Denial of Service | Client disconnect during streaming | mitigate | `http.NewRequestWithContext(c.Request.Context(), ...)` propagates cancellation; ElevenLabs aborts generation (Pitfall 7). Test `TestHandleTTSCancelPropagates` cancels `c.Request.Context()` and asserts upstream mock server sees connection close. |

    ```go
    // TTSClaims are the claims carried in an OBS-URL tts_token.
    // NOTE: no ExpiresAt field — D-08 mandates rotation-based revocation via
    // regenerating the per-overlay tts_signing_secret (see HandleRotateToken).
    type TTSClaims struct {
        Scope string `json:"scope"`
        jwt.RegisteredClaims
    }

    var ErrInvalidToken = errors.New("invalid tts_token")

    // SignOverlayToken produces a HS256-signed JWT for the given overlayID using
    // the per-overlay signing secret. The returned token is suitable for embedding
    // in the OBS browser-source URL as ?tts_token=... (D-08).
    func SignOverlayToken(overlayID string, signingSecret []byte) (string, error) {
        claims := TTSClaims{
            Scope: "tts:use",
            RegisteredClaims: jwt.RegisteredClaims{
                Subject:  overlayID,
                Issuer:   "all-chat",
                IssuedAt: jwt.NewNumericDate(time.Now()),
            },
        }
        token := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
        return token.SignedString(signingSecret)
    }

    // VerifyOverlayToken validates a tts_token against the expected overlayID and
    // per-overlay signing secret. Returns nil on success, non-nil error on any
    // validation failure (signature mismatch, scope/subject mismatch, alg confusion).
    func VerifyOverlayToken(tokenString, overlayID string, signingSecret []byte) error {
        if tokenString == "" {
            return ErrInvalidToken
        }
        parsed, err := jwt.ParseWithClaims(tokenString, &TTSClaims{}, func(t *jwt.Token) (any, error) {
            // Algorithm-confusion defence (T-13-02): accept HMAC only.
            if _, ok := t.Method.(*jwt.SigningMethodHMAC); !ok {
                return nil, fmt.Errorf("unexpected signing method: %v", t.Header["alg"])
            }
            return signingSecret, nil
        })
        if err != nil || parsed == nil || !parsed.Valid {
            return ErrInvalidToken
        }
        claims, ok := parsed.Claims.(*TTSClaims)
        if !ok {
            return ErrInvalidToken
        }
        if claims.Subject != overlayID {
            return ErrInvalidToken
        }
        if claims.Scope != "tts:use" {
            return ErrInvalidToken
        }
        return nil
    }
    ```

    ```go
    type TTSHandler struct {
        repo          ttsConfigStore
        overlays      overlayOwnershipChecker
        cipher        aesCipher
        httpClient    *http.Client
        logger        *zap.Logger
        publicBaseURL string                  // for building obs_url (env OVERLAY_PUBLIC_BASE_URL e.g. "https://allch.at")
        rateMu        sync.Mutex
        rateBuckets   map[string]*rateBucket  // per-overlay 60/min limiter
    }

    type rateBucket struct {
        count       int
        windowStart time.Time
    }

    const (
        ttsRateLimitPerMinute = 60
        elevenLabsBaseURL     = "https://api.elevenlabs.io"
    )

    func NewTTSHandler(repo ttsConfigStore, overlays overlayOwnershipChecker, cipher aesCipher, publicBaseURL string, logger *zap.Logger) *TTSHandler {
        return &TTSHandler{
            repo:          repo,
            overlays:      overlays,
            cipher:        cipher,
            httpClient:    &http.Client{Timeout: 30 * time.Second},
            logger:        logger,
            publicBaseURL: publicBaseURL,
            rateBuckets:   make(map[string]*rateBucket),
        }
    }

    // checkRateLimit returns true if the request is allowed, false if over the 60/min bucket.
    func (h *TTSHandler) checkRateLimit(overlayID string) bool {
        h.rateMu.Lock()
        defer h.rateMu.Unlock()
        now := time.Now()
        b, ok := h.rateBuckets[overlayID]
        if !ok || now.Sub(b.windowStart) >= time.Minute {
            h.rateBuckets[overlayID] = &rateBucket{count: 1, windowStart: now}
            return true
        }
        if b.count >= ttsRateLimitPerMinute {
            return false
        }
        b.count++
        return true
    }
    ```
