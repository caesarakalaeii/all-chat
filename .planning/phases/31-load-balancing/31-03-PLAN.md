    Create deployments/k8s/base/discord-listener/deployment.yaml — Deployment + Service in one file (same pattern as kick-listener/deployment.yaml):

    Deployment spec:
    - metadata.name: discord-listener, namespace: allchat
    - labels: app=discord-listener, component=listener, platform=discord
    - replicas: 1 (HPA manages scaling)
    - image: localhost:5000/allchat-discord-listener:latest, imagePullPolicy: Always
    - containerPort: 8086, name: http
    - resources: requests memory=128Mi cpu=100m; limits memory=512Mi cpu=500m
    - env vars from ConfigMaps/Secrets (same pattern as kick-listener):
      - PORT: "8086"
      - LOG_LEVEL: configMapKeyRef allchat-config/LOG_LEVEL
      - DATABASE_HOST/PORT/NAME/USER: configMapKeyRef allchat-config
      - DATABASE_PASSWORD: secretKeyRef allchat-secrets
      - REDIS_HOST/PORT: configMapKeyRef allchat-config
      - SOURCE_MANAGER_URL: configMapKeyRef allchat-config/SOURCE_MANAGER_URL
      - SOURCE_MANAGER_SECRET: secretKeyRef allchat-secrets/SERVICE_JWT_SECRET
      - DISCORD_BOT_TOKEN: secretKeyRef name=discord-listener-secrets key=DISCORD_BOT_TOKEN
    - livenessProbe: GET /health/live port 8086, initialDelaySeconds=30, periodSeconds=10, timeoutSeconds=5
    - readinessProbe: GET /health/ready port 8086, initialDelaySeconds=10, periodSeconds=5, timeoutSeconds=3

    Service spec (append as second document in same file with ---):
    - metadata.name: discord-listener, namespace: allchat
    - type: ClusterIP
    - ports: port=8086 targetPort=8086 protocol=TCP name=http
    - selector: app=discord-listener

    Create deployments/k8s/base/discord-listener/hpa.yaml:
    - apiVersion: autoscaling/v2
    - metadata.name: discord-listener, namespace: allchat
    - labels: app=discord-listener, component=listener, platform=discord
    - scaleTargetRef: apiVersion=apps/v1, kind=Deployment, name=discord-listener
    - minReplicas: 1, maxReplicas: 3
    - metrics: CPU averageUtilization=70, memory averageUtilization=80
    - behavior.scaleUp: stabilizationWindowSeconds=30, policies=[type=Pods value=1 periodSeconds=30]
    - behavior.scaleDown: stabilizationWindowSeconds=120, policies=[type=Pods value=1 periodSeconds=60]
    (Conservative scale-up — one pod at a time, 30s stabilization. Shard ownership lock prevents multiple pods from holding the Gateway; extra pods stand by for fast failover.)
  </action>
