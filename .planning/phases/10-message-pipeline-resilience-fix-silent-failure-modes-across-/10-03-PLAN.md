    2. In `consumeLoop` method (line ~117), replace the flat sleep:
       ```go
       // BEFORE (line ~131):
       time.Sleep(1 * time.Second)

       // AFTER:
       ```
       Replace with a backoff counter that increments on error and resets on success:
       ```go
       func (c *StreamConsumer) consumeLoop(ctx context.Context) {
           backoffAttempt := 0
           for {
               select {
               case <-ctx.Done():
                   return
               case <-c.stopCh:
                   return
               default:
               }

               err := c.readAndProcess(ctx)
               if err != nil {
                   if ctx.Err() != nil {
                       return
                   }
                   c.logger.Error("Error reading stream messages",
                       zap.Error(err),
                       zap.Int("backoff_attempt", backoffAttempt))
                   sleep := listener.JitteredBackoff(backoffAttempt)
                   backoffAttempt++
                   select {
                   case <-c.stopCh:
                       return
                   case <-ctx.Done():
                       return
                   case <-time.After(sleep):
                   }
                   continue
               }
               backoffAttempt = 0  // Reset on success
           }
       }
       ```
    3. IMPORTANT: `redis.Nil` from XREADGROUP (empty stream, no new messages) should NOT be treated as an error. Check how `readAndProcess` handles `redis.Nil` — if it returns `redis.Nil` as an error, filter it out before the backoff logic. The correct behavior is: `redis.Nil` means "no messages available" and should NOT trigger backoff.

    ```go
    c.logger.Error("dlq_write_failure",

    )
    ```
    This sentinel message `"dlq_write_failure"` enables Grafana Loki alerting. Keep any existing metric increment alongside the log.

    **F-07: Consumer group offset fix:**
    Find where `XGroupCreateMkStream` is called. If the offset argument is `"$"`:
    ```go
    // BEFORE:
    c.redisClient.XGroupCreateMkStream(ctx, c.stream, c.group, "$")

    // AFTER:
    c.redisClient.XGroupCreateMkStream(ctx, c.stream, c.group, "0")
    ```
    Using `"0"` means pre-existing messages in the stream will be consumed after a fresh consumer group creation (e.g., after a PEL wipe or first deployment). Using `"$"` silently drops all existing messages.

    Note: If the group already exists, `XGroupCreateMkStream` returns a `BUSYGROUP` error which should be silently ignored (existing behavior).
