    New implementation using a Redis sorted set where score = expiry timestamp:
    ```go
    func (m *Manager) RegisterPeer(ctx context.Context, platform, callerID string) (int, error) {
        key := fmt.Sprintf("peers:%s", platform)
        expiry := float64(time.Now().Add(m.peerTTL).Unix())

        // ZADD with the callerID as member and expiry timestamp as score
        // Overwrites existing member's score (re-registration updates expiry)
        if err := m.client.ZAdd(ctx, key, redis.Z{
            Score:  expiry,
            Member: callerID,
        }).Err(); err != nil {
            return 0, fmt.Errorf("failed to register peer: %w", err)
        }

        // Remove expired members (score < current time)
        now := fmt.Sprintf("%d", time.Now().Unix())
        m.client.ZRemRangeByScore(ctx, key, "-inf", now)

        // Count remaining (active) members
        count, err := m.client.ZCard(ctx, key).Result()
        if err != nil {
            return 0, fmt.Errorf("failed to count peers: %w", err)
        }

        // Set key TTL to prevent orphaned sorted sets (2x peerTTL)
        m.client.Expire(ctx, key, m.peerTTL*2)

        return int(count), nil
    }
    ```

    If `m.peerTTL` does not exist as a field, check what TTL the current individual `peer:platform:callerID` keys use (likely the same as `m.lockTTL` or a `PeerTTL` constant). Use the same value.

    Also update any `GetPeerCount` or similar methods that read peer data — they should also read from the sorted set now instead of scanning individual keys.

    Clean up: If there are helper methods that set/get individual `peer:platform:callerID` keys, update or remove them to use the sorted set approach.
