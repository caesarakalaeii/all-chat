   b. In `handlePatchCosmeticsLogic`, after gradient validation (Step 5), add avatar frame/flair logic (Step 5b):
      ```
      // Step 5b: Validate avatar frame/flair (premium gate)
      isPremium := false
      if v, ok := c.Get("is_premium"); ok && v != nil {
          if b, ok := v.(bool); ok { isPremium = b }
      }

      var avatarFrameID *uuid.UUID
      var avatarFlairID *uuid.UUID

      if !isPremium {
          // Downgrade enforcement: reject frame/flair if non-premium tries to set them
          if req.AvatarFrameID != nil && *req.AvatarFrameID != uuid.Nil {
              c.JSON(http.StatusForbidden, gin.H{"error": "avatar frames are a premium feature"})
              return
          }
          if req.AvatarFlairID != nil && *req.AvatarFlairID != uuid.Nil {
              c.JSON(http.StatusForbidden, gin.H{"error": "avatar flairs are a premium feature"})
              return
          }
          // Downgrade clear: pass explicit nil pointers that the repo will store as NULL
          nilUUID := uuid.Nil
          avatarFrameID = &nilUUID
          avatarFlairID = &nilUUID
      } else {
          // Premium user: pass through what was sent (nil pointer = field absent = no DB change needed)
          // Note: *uuid.UUID pointing to uuid.Nil = explicit clear; nil pointer = keep existing
          // Per RESEARCH.md Pattern 3: use req value directly
          avatarFrameID = req.AvatarFrameID
          avatarFlairID = req.AvatarFlairID
      }
      ```

   c. Update Step 6 call: `repo.UpsertViewerCosmetics(c.Request.Context(), viewerID, req.NameColor, nameGradientBytes, avatarFrameID, avatarFlairID)`

   d. Extend Step 7 response to include `avatar_frame_id` and `avatar_flair_id` in the JSON response.

   NOTE on the "absent field" contract: JSON unmarshaling into `*uuid.UUID` leaves it nil when the field is absent from the body. uuid.Nil (all zeros) represents an explicit null clear. The UPSERT in the repository treats both nil pointer (no DB change intended but UPSERT will overwrite) and &uuid.Nil (clear). The RESEARCH.md notes this is the caller's responsibility — the frontend sends `null` to clear and omits to keep existing. For simplicity in v1.4, the UPSERT always overwrites (consistent with how name_color works). Document this in a code comment.
