    Create innertube-rollout.json Grafana dashboard following research Pattern 3 structure:

    **Dashboard Metadata:**
    - Title: "YouTube Listener InnerTube Rollout"
    - Description: "Canary deployment monitoring with automatic promotion/rollback status"
    - Tags: ["youtube", "innertube", "canary", "rollout"]
    - Refresh: 30s (real-time monitoring during rollout)

    **Panel 1: Rollout Status (Stat panel, top-left)**
    - Query: `argo_rollouts_info{name="youtube-listener-innertube", namespace="allchat"}`
    - Display: Current rollout phase (Progressing, Paused, Degraded, Healthy)
    - Color mapping: Healthy=green, Progressing=blue, Paused=yellow, Degraded=red

    **Panel 2: Canary Weight (Gauge panel, top-center)**
    - Query: `argo_rollouts_canary_weight{name="youtube-listener-innertube", namespace="allchat"}`
    - Display: Current traffic percentage to canary (0-100%)
    - Thresholds: 0-10%=green, 10-50%=yellow, 50-100%=orange

    **Panel 3: Analysis Run Status (Table panel, top-right)**
    - Query: `argo_rollouts_analysis_run_info{rollout="youtube-listener-innertube", namespace="allchat"}`
    - Display: Current and historical analysis runs with success/failure status
    - Columns: Run Name, Phase, Status, Start Time

    **Panel 4: Error Rate Comparison (Time series, middle-left)**
    - Query 1 (InnerTube): `sum(rate(youtube_listener_errors_total{service="youtube-listener-innertube-canary"}[5m])) / sum(rate(youtube_listener_requests_total{service="youtube-listener-innertube-canary"}[5m]))`
    - Query 2 (Official): `sum(rate(youtube_listener_errors_total{service="youtube-listener"}[5m])) / sum(rate(youtube_listener_requests_total{service="youtube-listener"}[5m]))`
    - Thresholds: <1%=green (promotion gate), 1-5%=yellow, >5%=red (rollback trigger)
    - Legend: "InnerTube Canary", "Official Listener Baseline"

    **Panel 5: Message Rate Comparison (Time series, middle-right)**
    - Query 1 (InnerTube): `sum(rate(youtube_listener_messages_published_total{service="youtube-listener-innertube-canary"}[5m]))`
    - Query 2 (Official): `sum(rate(youtube_listener_messages_published_total{service="youtube-listener"}[5m]))`
    - Display: Messages per second for both services
    - Thresholds: <5% deviation from baseline

    **Panel 6: Redis Publish Success Rate (Time series, bottom-left)**
    - Query: `sum(rate(youtube_listener_redis_publish_success_total{service="youtube-listener-innertube-canary"}[5m])) / sum(rate(youtube_listener_redis_publish_attempts_total{service="youtube-listener-innertube-canary"}[5m]))`
    - Thresholds: >99%=green, 95-99%=yellow, <95%=red (rollback trigger)

    **Panel 7: Pod Restart Rate (Time series, bottom-center)**
    - Query: `sum(rate(kube_pod_container_status_restarts_total{namespace="allchat", pod=~"youtube-listener-innertube-.*"}[5m])) * 60`
    - Display: Restarts per minute
    - Thresholds: 0=green, >0=yellow, >2=red (rollback trigger)

    **Panel 8: Reconnection Frequency (Time series, bottom-right)**
    - Query: `sum(rate(youtube_listener_reconnections_total{service="youtube-listener-innertube-canary"}[5m]))`
    - Display: Reconnections per second
    - Purpose: Monitor InnerTube polling stability

    **Dashboard Variables:**
    - `$datasource`: Prometheus datasource selector
    - `$namespace`: Namespace filter (default: allchat)

    **Why this layout:** Research Pattern 3 - top row for rollout status (what's happening), middle rows for metric comparison (why it's happening), bottom row for detailed diagnostics.

    Create ROLLOUT_GUIDE.md operator runbook for canary deployment:

    **Structure:**

    **1. Prerequisites**
    - Argo Rollouts controller installed in cluster
    - kubectl-argo-rollouts CLI plugin installed
    - Prometheus and Grafana operational
    - Official YouTube listener running and healthy (baseline for comparison)

    **2. Pre-Deployment Checklist**
    - [ ] Verify official listener message rate baseline: `kubectl top pods -n allchat -l app=youtube-listener`
    - [ ] Check Prometheus scraping InnerTube metrics: `curl http://youtube-listener-innertube:8080/metrics`
    - [ ] Confirm ServiceMonitor created: `kubectl get servicemonitor youtube-listener-innertube -n allchat`
    - [ ] Review recent changes: `git log --oneline services/youtube-listener-innertube/`

    **3. Deployment Steps**
    ```bash
    # 1. Apply Argo Rollouts manifests
    kubectl apply -k deployments/k8s/youtube-listener-innertube/production/

    # 2. Verify Rollout created
    kubectl get rollout youtube-listener-innertube -n allchat

    # 3. Watch rollout progress (real-time)
    kubectl argo rollouts get rollout youtube-listener-innertube -n allchat --watch

    # 4. Open Grafana dashboard for metrics monitoring
    # Navigate to: Dashboards > YouTube Listener InnerTube Rollout
    ```

    **4. Rollout Timeline (Expected)**
    - **0-5 min:** Initial deployment, canary pods starting
    - **5 min - 4 hours:** 10% canary soak with continuous analysis
    - **4 hours - 8 hours:** 50% canary soak (if 10% passed analysis)
    - **8 hours - 8.5 hours:** Full promotion to 100% (if 50% passed analysis)

    **5. Monitoring During Rollout**
    - Watch analysis runs: `kubectl get analysisrun -n allchat`
    - Check canary weight: `kubectl argo rollouts status youtube-listener-innertube -n allchat`
    - Review Grafana dashboard: Error rate <1%, message rate within 5% of baseline
    - Spot-check logs: `kubectl logs -n allchat -l app=youtube-listener-innertube,rollouts-pod-template-hash=<canary-hash>`

    **6. Manual Promotion (Emergency Use)**
    ```bash
    # Promote to next step immediately (skip soak)
    kubectl argo rollouts promote youtube-listener-innertube -n allchat
    ```

    **7. Manual Rollback**
    ```bash
    # Abort rollout and revert to stable version
    kubectl argo rollouts abort youtube-listener-innertube -n allchat

    # Check rollback progress
    kubectl argo rollouts get rollout youtube-listener-innertube -n allchat --watch
    ```

    **8. Post-Deployment Validation**
    - Verify 100% traffic on InnerTube: `kubectl argo rollouts status youtube-listener-innertube -n allchat`
    - Compare message counts with official listener: Check Grafana "Message Rate Comparison" panel
    - Validate offline detection: Stop a live stream, confirm InnerTube stops polling
    - Monitor for 24 hours: Check error rate remains <1%

    **9. Fix-in-Place Workflow (User requirement from 12-CONTEXT.md)**
    If issues discovered during canary soak:
    1. Keep rollout at current percentage (do not abort)
    2. Deploy fix to InnerTube image: `docker build -t allchat/youtube-listener-innertube:v1.2.1 .`
    3. Update image tag in `deployments/k8s/youtube-listener-innertube/production/kustomization.yaml`
    4. Apply: `kubectl apply -k deployments/k8s/youtube-listener-innertube/production/`
    5. Argo Rollouts will update canary pods with new image
    6. If fix successful, rollout resumes promotion after analysis passes

    **10. Troubleshooting Quick Reference**
    - Rollout stuck in Paused: Check analysis run status, may be waiting for metrics to stabilize
    - Automatic rollback triggered: Check Grafana for threshold breaches (>5% error rate, >20% message deviation)
    - Canary pods crashlooping: Check logs for startup errors, verify environment variables and Redis connectivity
    - Promotion not progressing: Verify AnalysisTemplate queries return valid results: `kubectl describe analysisrun <name> -n allchat`

    **Why manual promotion option:** Research suggests manual override for emergency situations, but emphasizes automatic promotion is preferred (per 12-CONTEXT.md decision).

    Create comprehensive troubleshooting guide and update InnerTube README:

    **1. docs/deployment/TROUBLESHOOTING_INNERTUBE.md:**

    **Structure:**

    **Issue 1: Automatic Rollback Triggered**
    - Symptoms: Rollout status changes to "Degraded", canary traffic returns to 0%, AnalysisRun shows "Failed"
    - Diagnosis:
      - Check which metric breached threshold: `kubectl describe analysisrun <name> -n allchat | grep -A 5 "Failed"`
      - Review Grafana dashboard for spike in error rate or message rate deviation
      - Check canary pod logs for errors: `kubectl logs -n allchat -l rollouts-pod-template-hash=<canary-hash>`
    - Resolution:
      - If error rate >5%: Investigate InnerTube API changes, check HTTP response codes in logs
      - If message rate drops >20%: Check Redis connectivity, verify channel assignments via source-manager
      - If Redis publish failures: Check Redis health, verify network policies
      - Deploy fix, restart rollout: `kubectl argo rollouts restart youtube-listener-innertube -n allchat`

    **Issue 2: Rollout Stuck at 10% for >6 Hours**
    - Symptoms: Canary weight remains at 10%, analysis runs continuously but doesn't promote
    - Diagnosis:
      - Check analysis success rate: `kubectl get analysisrun -n allchat` (look for Phase: Running, Status: Progressing)
      - Verify metrics return valid data: `curl http://prometheus.monitoring.svc.cluster.local:9090/api/v1/query?query=<promql>` (test each AnalysisTemplate query)
      - Check if error rate oscillating around 1% threshold: Review Grafana error rate panel
    - Resolution:
      - If metrics unavailable: Verify ServiceMonitor scraping, check Prometheus targets: `kubectl get servicemonitor -n allchat`
      - If error rate hovering at 0.9-1.1%: Metrics haven't stabilized, wait for 240 consecutive successes
      - If stuck indefinitely: Manual promotion (emergency only): `kubectl argo rollouts promote youtube-listener-innertube -n allchat`

    **Issue 3: Thundering Herd During Rollback (Research Pitfall 1)**
    - Symptoms: Official listener CPU spikes to >80% immediately after rollback, Redis connection errors
    - Diagnosis:
      - Check official listener resource usage: `kubectl top pods -n allchat -l app=youtube-listener`
      - Review official listener HPA: `kubectl get hpa youtube-listener -n allchat`
      - Check Redis connection pool: `redis-cli INFO clients | grep connected_clients`
    - Resolution:
      - Immediate: Scale official listener manually if HPA not responsive: `kubectl scale deployment youtube-listener -n allchat --replicas=15`
      - Long-term: Ensure HPA configured with lower CPU threshold (50-60% instead of 80%)
      - Prevention: Verify `terminationGracePeriodSeconds: 30` in Rollout manifest

    **Issue 4: Canary Pods Crashlooping**
    - Symptoms: Canary pods restart every 30-60 seconds, readiness probe failures
    - Diagnosis:
      - Check pod events: `kubectl describe pod <canary-pod> -n allchat`
      - Review logs: `kubectl logs <canary-pod> -n allchat --previous`
      - Verify environment variables: `kubectl get rollout youtube-listener-innertube -n allchat -o yaml | grep -A 10 env:`
    - Resolution:
      - Missing Redis connection: Check REDIS_HOST environment variable, verify Redis service: `kubectl get svc redis -n allchat`
      - Source-manager authentication failure: Verify SOURCE_MANAGER_SECRET, check source-manager logs
      - Image pull errors: Verify image tag exists: `docker images | grep youtube-listener-innertube`

    **Issue 5: Message Rate Deviation >5% but <20% (Not Rolling Back)**
    - Symptoms: Grafana shows 7-15% message rate difference, analysis continues, no rollback
    - Diagnosis:
      - Check if difference is consistent or intermittent: Review 5-minute rate window
      - Verify both services processing same channel set: `kubectl logs -n allchat <canary-pod> | grep "channel_id"`
      - Compare per-channel message rates: Prometheus query `youtube_listener_messages_published_total` grouped by channel_id
    - Resolution:
      - If consistent 7-15% deviation: May indicate InnerTube parsing differences (not a failure, but investigate)
      - If intermittent spikes: Normal variance, wait for analysis to accumulate more samples
      - If specific channels missing from InnerTube: Check source-manager channel assignment, verify stream discovery

    **Issue 6: Fix-in-Place Not Applying to Canary Pods**
    - Symptoms: Updated image deployed, but canary pods still running old version
    - Diagnosis:
      - Check Rollout image: `kubectl get rollout youtube-listener-innertube -n allchat -o yaml | grep image:`
      - Verify Kustomize applied: `kubectl kustomize deployments/k8s/youtube-listener-innertube/production/ | grep newTag`
      - Check pod template hash: `kubectl get rs -n allchat -l app=youtube-listener-innertube` (compare hashes)
    - Resolution:
      - If image not updated: Reapply Kustomize: `kubectl apply -k deployments/k8s/youtube-listener-innertube/production/ --force`
      - If ReplicaSet not rolling: Manual restart: `kubectl argo rollouts restart youtube-listener-innertube -n allchat`
      - If persistent: Abort rollout, apply fix to stable, restart rollout from 0%

    **Common Commands:**
    ```bash
    # View rollout status
    kubectl argo rollouts get rollout youtube-listener-innertube -n allchat

    # Check analysis runs
    kubectl get analysisrun -n allchat
    kubectl describe analysisrun <name> -n allchat

    # View canary pod logs
    kubectl logs -n allchat -l app=youtube-listener-innertube,rollouts-pod-template-hash=<canary-hash> --tail=100

    # Abort and rollback
    kubectl argo rollouts abort youtube-listener-innertube -n allchat

    # Manual promotion (emergency)
    kubectl argo rollouts promote youtube-listener-innertube -n allchat
    ```
