  <action>
    Create rollout.yaml implementing canary deployment strategy from research Pattern 1:

    **Rollout Configuration:**
    - `kind: Rollout` (replaces standard Deployment)
    - `metadata.name: youtube-listener-innertube`
    - `metadata.namespace: allchat` (matches existing namespace from codebase)
    - `spec.replicas: 10` (production scale - will be patched by overlay)
    - `spec.revisionHistoryLimit: 3` (keep last 3 rollout versions)
    - `spec.selector.matchLabels: {app: youtube-listener-innertube}`

    **Pod Template:**
    - `metadata.labels: {app: youtube-listener-innertube, version: innertube}`
    - `metadata.annotations: {prometheus.io/scrape: "true", prometheus.io/port: "8080", prometheus.io/path: "/metrics"}`
    - `spec.terminationGracePeriodSeconds: 30` (graceful shutdown - matches existing main.go 25s timeout + 5s buffer)
    - `spec.containers[0].lifecycle.preStop.exec.command: ["/bin/sh", "-c", "sleep 5"]` (stagger terminations per research Pitfall 1)
    - Container: `image: allchat/youtube-listener-innertube:latest`, ports: 8080, env: LOG_LEVEL, REDIS_HOST (from ConfigMap)
    - Resources: `requests: {cpu: 200m, memory: 256Mi}`, `limits: {cpu: 1000m, memory: 1Gi}`
    - Probes: `livenessProbe: /health/live`, `readinessProbe: /health/ready` (existing endpoints from Phase 9)

    **Canary Strategy (per 12-CONTEXT.md decisions):**
    - `strategy.canary.canaryService: youtube-listener-innertube-canary`
    - `strategy.canary.stableService: youtube-listener-innertube-stable`
    - `strategy.canary.trafficRouting.managedRoutes: [{name: primary}]` (native K8s, no service mesh)
    - `strategy.canary.steps`:
      1. `setWeight: 10` (10% traffic to canary = 1 pod if 10 total replicas)
      2. `pause: {}` (indefinite - controlled by analysis, not clock per research Pitfall 2)
      3. `analysis: {templates: [{templateName: innertube-metrics-analysis}], args: [{name: service-name, value: youtube-listener-innertube-canary}, {name: baseline-service, value: youtube-listener}]}`
      4. `setWeight: 50` (promote to 50% if analysis passes)
      5. `pause: {}`
      6. `analysis: {...}` (repeat analysis at 50%)
      7. `setWeight: 100` (full promotion)

    **Why indefinite pause:** Research Pitfall 2 - let AnalysisTemplate control promotion via metrics, not arbitrary 4-hour clock. Analysis interval * count = effective soak time.
  </action>

<task type="auto">
  <name>Create AnalysisTemplate with Prometheus queries</name>
  <files>
    deployments/k8s/youtube-listener-innertube/base/analysis-template.yaml
  </files>
  <action>
    Create analysis-template.yaml with PromQL queries for automatic promotion/rollback (research Pattern 2):

    **AnalysisTemplate Configuration:**
    - `kind: AnalysisTemplate`
    - `metadata.name: innertube-metrics-analysis`
    - `metadata.namespace: allchat`
    - `spec.args: [{name: service-name}, {name: baseline-service}]` (templated for canary vs official listener)

    **Metric 1: Error Rate (promotion gate <1%, rollback trigger >5%)**
    ```yaml
    - name: error-rate
      interval: 1m  # Check every minute
      count: 240    # 240 samples = 4 hours (user requirement for soak time)
      successCondition: result < 0.01  # <1% error rate
      failureCondition: result > 0.05  # >5% error rate triggers rollback
      failureLimit: 3  # 3 consecutive failures = rollback
      provider:
        prometheus:
          address: http://prometheus.monitoring.svc.cluster.local:9090
          query: |
            sum(rate(youtube_listener_errors_total{service="{{args.service-name}}"}[5m]))
            /
            sum(rate(youtube_listener_requests_total{service="{{args.service-name}}"}[5m]))
    ```

    **Metric 2: Message Rate Deviation (promotion <5%, rollback >20%)**
    ```yaml
    - name: message-rate-deviation
      interval: 1m
      count: 240
      successCondition: result < 0.05  # <5% deviation from baseline
      failureCondition: result > 0.20  # >20% deviation triggers rollback
      failureLimit: 5  # Allow variance, rollback after 5 consecutive
      provider:
        prometheus:
          address: http://prometheus.monitoring.svc.cluster.local:9090
          query: |
            abs(
              sum(rate(youtube_listener_messages_published_total{service="{{args.service-name}}"}[5m]))
              -
              sum(rate(youtube_listener_messages_published_total{service="{{args.baseline-service}}"}[5m]))
            )
            /
            sum(rate(youtube_listener_messages_published_total{service="{{args.baseline-service}}"}[5m]))
    ```

    **Metric 3: Redis Publish Success (promotion >99%, rollback <95%)**
    ```yaml
    - name: redis-publish-success
      interval: 1m
      count: 240
      successCondition: result > 0.99
      failureCondition: result < 0.95  # Downstream failure
      failureLimit: 2  # Fast rollback on Redis issues
      provider:
        prometheus:
          address: http://prometheus.monitoring.svc.cluster.local:9090
          query: |
            sum(rate(youtube_listener_redis_publish_success_total{service="{{args.service-name}}"}[5m]))
            /
            sum(rate(youtube_listener_redis_publish_attempts_total{service="{{args.service-name}}"}[5m]))
    ```

    **Metric 4: Pod Restart Rate (0 restarts = success, >2/min = rollback)**
    ```yaml
    - name: pod-restart-rate
      interval: 1m
      count: 240
      successCondition: result == 0
      failureCondition: result > 2  # Crashloop
      failureLimit: 1  # Immediate rollback on crashloop
      provider:
        prometheus:
          address: http://prometheus.monitoring.svc.cluster.local:9090
          query: |
            sum(rate(kube_pod_container_status_restarts_total{
              namespace="allchat",
              pod=~"youtube-listener-innertube-.*"
            }[5m])) * 60
    ```

    **Why count: 240:** 240 minutes = 4 hours of continuous analysis (user requirement for conservative soak duration per 12-CONTEXT.md).
  </action>
  <verify>
    cat deployments/k8s/youtube-listener-innertube/base/analysis-template.yaml | grep -E "kind: AnalysisTemplate|interval: 1m|count: 240|successCondition|failureCondition"
  </verify>

    Create remaining Kubernetes manifests for canary traffic routing and Prometheus monitoring:

    **1. base/service.yaml - Stable and Canary Services:**
    ```yaml
    ---
    apiVersion: v1
    kind: Service
    metadata:
      name: youtube-listener-innertube-stable
      namespace: allchat
    spec:
      selector:
        app: youtube-listener-innertube
      ports:
        - name: http
          port: 8080
          targetPort: 8080
    ---
    apiVersion: v1
    kind: Service
    metadata:
      name: youtube-listener-innertube-canary
      namespace: allchat
    spec:
      selector:
        app: youtube-listener-innertube
      ports:
        - name: http
          port: 8080
          targetPort: 8080
    ```
    **Why two Services:** Argo Rollouts uses label manipulation to route traffic - stable Service points to stable ReplicaSet, canary Service points to canary ReplicaSet (research Pattern 1).

    **2. base/kustomization.yaml:**
    ```yaml
    apiVersion: kustomize.config.k8s.io/v1beta1
    kind: Kustomization

    namespace: allchat

    resources:
      - rollout.yaml
      - service.yaml
      - analysis-template.yaml
    ```

    **3. production/kustomization.yaml:**
    ```yaml
    apiVersion: kustomize.config.k8s.io/v1beta1
    kind: Kustomization

    namespace: allchat

    resources:
      - ../base

    images:
      - name: allchat/youtube-listener-innertube
        newTag: v1.2.0  # Updated by CI/CD

    patchesStrategicMerge:
      - rollout-patch.yaml
    ```

    **4. production/rollout-patch.yaml:**
    ```yaml
    apiVersion: argoproj.io/v1alpha1
    kind: Rollout
    metadata:
      name: youtube-listener-innertube
    spec:
      replicas: 10  # Production scale (10% = 1 pod, 50% = 5 pods)
    ```

    **5. monitoring/servicemonitor-innertube.yaml (research Pattern 2):**
    ```yaml
    apiVersion: monitoring.coreos.com/v1
    kind: ServiceMonitor
    metadata:
      name: youtube-listener-innertube
      namespace: allchat
      labels:
        app: youtube-listener-innertube
        prometheus: kube-prometheus  # Matches Prometheus selector
    spec:
      selector:
        matchLabels:
          app: youtube-listener-innertube
      endpoints:
        - port: http
          path: /metrics
          interval: 1m  # Matches analysis interval
          scrapeTimeout: 10s
    ```

    **Why ServiceMonitor:** Prometheus Operator pattern - auto-discovers pods with matching labels, no manual Prometheus config edits (research standard stack).
