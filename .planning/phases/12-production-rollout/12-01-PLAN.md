    **Required Metrics (aligned with AnalysisTemplate requirements):**

    1. Error tracking (for error rate threshold):
       - `youtube_listener_errors_total` (counter) with labels: service, error_type (http, parse, rate_limit, redis)
       - `youtube_listener_requests_total` (counter) with labels: service

    2. Message publishing (for message rate comparison):
       - `youtube_listener_messages_published_total` (counter) with labels: service, channel_id

    3. Redis health (for downstream failure detection):
       - `youtube_listener_redis_publish_success_total` (counter) with labels: service
       - `youtube_listener_redis_publish_attempts_total` (counter) with labels: service
       - `youtube_listener_redis_publish_latency_seconds` (histogram) with labels: service

    4. Reconnection tracking (for stability monitoring):
       - `youtube_listener_reconnections_total` (counter) with labels: service, channel_id, reason

    **Implementation:**
    - Use `prometheus/client_golang` (already in go.mod via shared module)
    - Use `promauto.New*Vec` for automatic registration
    - Service label value: "youtube-listener-innertube-canary" (matches Kubernetes Service name from research)
    - Match metric names EXACTLY to official listener for PromQL compatibility
    - Add struct type `InnerTubeMetrics` with all metric fields
    - Add constructor `NewInnerTubeMetrics() *InnerTubeMetrics`

    **Why matching official listener names:** AnalysisTemplate uses same PromQL queries for both services, only changing service label selector.
