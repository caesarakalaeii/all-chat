    Leadership-only listeners (youtube-innertube, discord, youtube) do NOT call `base.Start(ctx, mgr)` so they don't get the SDK's demand subscriber loop automatically. They manage their own streams via custom code.

    For each of these listeners, add a direct Redis Pub/Sub subscription to `source:demand` in their main.go.

    **Pattern for all three (adapt platform string for each):**

    Add a goroutine after the existing startup sequence that subscribes to `source:demand`:

    ```go
    // Demand-driven activation (Phase 5)
    go func() {
        platformFilter := "youtube-innertube" // or "discord" or "youtube"
        pubsub := redisClient.Subscribe(ctx, "source:demand")
        defer pubsub.Close()

        logger.Info("Subscribed to source:demand for demand-driven activation",
            zap.String("platform", platformFilter))

        for {
            msg, err := pubsub.ReceiveMessage(ctx)
            if err != nil {
                if ctx.Err() != nil {
                    return
                }
                logger.Error("Demand subscriber error, retrying",
                    zap.Error(err))
                time.Sleep(time.Second)
                continue
            }

            var update struct {
                Type    string `json:"type"`
                Sources []struct {
                    SourceID  string `json:"source_id"`
                    ChannelID string `json:"channel_id"`
                    Platform  string `json:"platform"`
                    OverlayID string `json:"overlay_id"`
                } `json:"sources"`
            }
            if err := json.Unmarshal([]byte(msg.Payload), &update); err != nil {
                logger.Warn("Failed to parse demand update", zap.Error(err))
                continue
            }

            // Filter to this platform
            demanded := make(map[string]bool)
            for _, s := range update.Sources {
                if s.Platform == platformFilter {
                    demanded[s.ChannelID] = true
                }
            }

            logger.Info("Demand update received",
                zap.Int("total_sources", len(update.Sources)),
                zap.Int("platform_sources", len(demanded)))

            // Pass demanded set to stream manager
            streamManager.UpdateDemandedStreams(demanded)
        }
    }()
    ```

    **For each listener, the stream manager needs an `UpdateDemandedStreams(demanded map[string]bool)` method** (or equivalent). This method should:
    - Store the demanded set
    - Disconnect streams that lost demand
    - Allow connection of demanded streams on the next reconciliation cycle

    HOWEVER: This is complex per-listener work. The exact implementation depends on how each listener's stream manager works internally.

    **Pragmatic approach:** For this plan, add the Pub/Sub subscription goroutine and a log line showing demanded sources. The actual connect/disconnect logic per leadership-only listener should be a follow-up if needed. The PRIMARY target (TikTok) and the SDK-integrated listeners (kick, twitch-eventsub) are already handled.

    For youtube-innertube:
    - Platform filter: check what platform string innertube sources use in `overlay_chat_sources.platform`. Likely `"youtube"` (shared with youtube-listener).
    - Stream manager: `streams.Manager` — add `UpdateDemandedStreams` or similar.

    For discord-listener:
    - Platform filter: `"discord"`
    - The discord listener manages shard-based channel subscriptions, not stream-based. Demand means "at least one overlay has this discord channel as a source."

    For youtube-listener:
    - Platform filter: `"youtube"`
    - The youtube listener manages stream polling per channel.

    **MINIMUM for this task:** Add the Pub/Sub subscription goroutine to each listener's main.go that receives demand updates, filters by platform, and logs the update. Wire a no-op or minimal `UpdateDemandedStreams` into the stream manager that at minimum stores the demanded set. Full connect/disconnect gating can be refined iteratively.

    Import additions needed: `"encoding/json"` if not already imported, and `"time"` for retry backoff.
