<objective>
Build the demand signal infrastructure in source-manager: subscribe to overlay connection events from API Gateway, resolve which chat sources have active demand by querying the database, maintain an in-memory demand set, and publish full-replacement DemandUpdate snapshots to a new `source:demand` Redis Pub/Sub channel. Add a fallback HTTP endpoint for listeners to poll.

Purpose: Source-manager becomes the sole authority for "which sources have demand", decoupling listeners from direct Redis key scanning and DB queries.
Output: New `demand/` package in source-manager with subscriber, handler, and tests; repository extended with overlay-to-source lookup.
</objective>

    **Step 1: Add GetSourcesForOverlays to repository.go**

    Add this method to the existing Repository struct in `services/source-manager/registry/repository.go`:

    ```go
    func (r *Repository) GetSourcesForOverlays(ctx context.Context, overlayIDs []string) ([]*models.ActiveSource, error)
    ```

    SQL query:
    ```sql
    SELECT ocs.id, ocs.overlay_id, ocs.platform, ocs.channel_id,
           COALESCE(ocs.config->>'stream_id', '') as stream_id,
           o.is_active, ocs.created_at, ocs.updated_at
    FROM overlay_chat_sources ocs
    JOIN overlays o ON ocs.overlay_id = o.id
    JOIN users u ON o.user_id = u.id
    WHERE o.is_active = true
      AND u.is_banned = false
      AND ocs.overlay_id = ANY($1::uuid[])
    ORDER BY ocs.platform, ocs.created_at
    ```

    **Step 2: Create demand/subscriber.go**

    Define the DemandUpdate type:
    ```go
    type DemandSource struct {
        SourceID  string `json:"source_id"`
        ChannelID string `json:"channel_id"`
        Platform  string `json:"platform"`
        OverlayID string `json:"overlay_id"`
    }

    type DemandUpdate struct {
        Type      string         `json:"type"`      // always "demand_update"
        Sources   []DemandSource `json:"sources"`
        Timestamp string         `json:"timestamp"` // ISO 8601
    }
    ```

    Define OverlayDemandSubscriber struct:
    ```go
    type OverlayDemandSubscriber struct {
        redisClient *redis.Client
        repo        *registry.Repository
        logger      *zap.Logger
        mu          sync.RWMutex
        // demand tracks overlay_id -> []DemandSource
        demand      map[string][]DemandSource
    }
    ```

    Constructor: `NewOverlayDemandSubscriber(redisClient *redis.Client, repo *registry.Repository, logger *zap.Logger) *OverlayDemandSubscriber`

    Methods:
    - `Start(ctx context.Context) error` — (1) scan `overlay:connected:*` keys via `redisClient.Keys(ctx, "overlay:connected:*")`, (2) extract overlay IDs, (3) call `repo.GetSourcesForOverlays(ctx, overlayIDs)` to hydrate demand map, (4) publish initial DemandUpdate, (5) subscribe to `overlay:connections` channel
    - `handleConnectionEvent(ctx context.Context, message string)` — parse OverlayConnectionEvent JSON, on "connected": query `repo.GetSourcesForOverlays(ctx, []string{event.OverlayID})` and add to demand map, on "disconnected": remove overlay from demand map. After any change: call `publishDemandUpdate(ctx)`.
    - `publishDemandUpdate(ctx context.Context)` — flatten demand map into []DemandSource, build DemandUpdate{Type: "demand_update", Sources: flatSources, Timestamp: time.Now().UTC().Format(time.RFC3339)}, JSON marshal, `redisClient.Publish(ctx, "source:demand", payload)`
    - `GetDemandedSources() []DemandSource` — returns current demand snapshot (read-locked)
    - `GetDemandedSourcesByPlatform(platform string) []DemandSource` — filters by platform

    CRITICAL: Start() MUST complete hydration scan and publish initial DemandUpdate BEFORE subscribing to live events. This prevents Pitfall 3 (source-manager publishes empty demand on restart).

    The Subscribe loop follows the exact pattern from `shared/listener/base.go startMigrationSubscriberLoop`: outer retry loop with exponential backoff (1s to 30s), context cancellation check.

    ```go
    func NewDemandHandler(subscriber *OverlayDemandSubscriber) *DemandHandler

    ```

    `GetDemand` reads optional `platform` query param. If present, returns `subscriber.GetDemandedSourcesByPlatform(platform)`. Otherwise returns all. Response format: `{"sources": [...DemandSource]}`.
