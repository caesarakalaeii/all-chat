<objective>
Harden the message-processor stream consumer to eliminate 8 silent failure modes (MP-01 through MP-08) and create the DLQ infrastructure (DQ-01, DQ-02, DQ-03).

Purpose: The message-processor has 3 replicas in production all registering as "processor-1" — PEL entries are permanently orphaned, messages are silently lost on Redis unavailability, and there is no dead-letter routing for unprocessable messages.

Output: Resilient stream consumer with unique consumer names, PEL drain on startup, exponential backoff retry, DLQ routing, and admin replay endpoint.
</objective>
