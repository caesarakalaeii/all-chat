    Find or create the alert rules file in caesar-deployment. Check kustomization.yaml to understand the resource format. If no PrometheusRule exists yet, create one as a PrometheusRule CRD (standard Kubernetes format for prometheus-operator).

    Add 5 alert rules (note: 5 not 4 — includes pubsub_reconnect_total per D-14/D-15):

    **1. DLQ Depth Non-Zero (D-17):**
    ```yaml
    - alert: AllChatDLQDepthNonZero
      expr: sum(rate(dlq_messages_total[5m])) > 0
      for: 5m
      labels:
        severity: critical
        team: allchat
      annotations:
        summary: "Dead-letter queue has accumulated messages"
        description: "DLQ messages detected for {{ $labels.source_service }} (reason: {{ $labels.reason }}). Messages are failing processing and landing in chat:dlq."
    ```

    **2. PEL Pending High:**
    ```yaml
    - alert: AllChatPELPendingHigh
      expr: sum(pel_pending_messages) > 100
      for: 10m
      labels:
        severity: warning
        team: allchat
      annotations:
        summary: "Redis Streams PEL has high pending message count"
        description: "{{ $value }} messages pending in PEL — indicates consumer processing backup or crashed consumers."
    ```

    **3. Ring Buffer Drops:**
    ```yaml
    - alert: AllChatRingBufferDrops
      expr: rate(ring_buffer_drops_total[5m]) > 0
      for: 5m
      labels:
        severity: warning
        team: allchat
      annotations:
        summary: "Listener ring buffer dropping messages"
        description: "{{ $labels.service }} listener ring buffer is full and dropping messages. Redis may be unavailable."
    ```

    **4. Publish Retry Exhaustion:**
    ```yaml
    - alert: AllChatPublishRetryExhausted
      expr: rate(publish_retry_total{attempt="exhausted"}[5m]) > 0
      for: 5m
      labels:
        severity: critical
        team: allchat
      annotations:
        summary: "Message publish retries exhausted"
        description: "Pub/Sub publish operations failing after 3 retry attempts. Messages being routed to DLQ."
    ```

    **5. Pub/Sub Reconnect (D-14, D-15 — was missing in original plan):**
    ```yaml
    - alert: AllChatPubSubReconnect
      expr: rate(pubsub_reconnect_total[5m]) > 0
      for: 5m
      labels:
        severity: warning
        team: allchat
      annotations:
        summary: "Pub/Sub reconnect events detected"
        description: "{{ $labels.service }} is reconnecting to Redis Pub/Sub (overlay: {{ $labels.overlay_id }}). Brief reconnects are expected; sustained reconnects indicate Redis instability."
    ```

    **Important format note:** If using PrometheusRule CRD, do NOT use `noDataState` field — that is a Grafana alerting concept, not a PrometheusRule CRD field. PrometheusRule CRDs use standard fields: `alert`, `expr`, `for`, `labels`, `annotations`. If the existing format uses ConfigMap-based Grafana alerts, then `noDataState: OK` is valid.
