    Find the existing alert rules file in caesar-deployment. It may be a PrometheusRule CRD or a ConfigMap — read the Phase 4 alert SUMMARY or search for `allchat-alerts` or `PrometheusRule` in the workloads directory.

    Add 4 new alert rules to the existing alert groups, following the Phase 4 pattern:

    **1. DLQ Depth Non-Zero (D-17):**
    ```yaml
    - alert: AllChatDLQDepthNonZero
      expr: sum(rate(dlq_messages_total[5m])) > 0
      for: 5m
      labels:
        severity: critical
        team: allchat
      annotations:
        summary: "Dead-letter queue has accumulated messages"
        description: "DLQ messages detected for {{ $labels.source_service }} (reason: {{ $labels.reason }}). Messages are failing processing and landing in chat:dlq."
    ```

    **2. PEL Pending High:**
    ```yaml
    - alert: AllChatPELPendingHigh
      expr: sum(pel_pending_messages) > 100
      for: 10m
      labels:
        severity: warning
        team: allchat
      annotations:
        summary: "Redis Streams PEL has high pending message count"
        description: "{{ $value }} messages pending in PEL — indicates consumer processing backup or crashed consumers."
    ```

    **3. Ring Buffer Drops:**
    ```yaml
    - alert: AllChatRingBufferDrops
      expr: rate(ring_buffer_drops_total[5m]) > 0
      for: 5m
      labels:
        severity: warning
        team: allchat
      annotations:
        summary: "Listener ring buffer dropping messages"
        description: "{{ $labels.service }} listener ring buffer is full and dropping messages. Redis may be unavailable."
    ```

    **4. Publish Retry Exhaustion:**
    ```yaml
    - alert: AllChatPublishRetryExhausted
      expr: rate(publish_retry_total{attempt="exhausted"}[5m]) > 0
      for: 5m
      labels:
        severity: critical
        team: allchat
      annotations:
        summary: "Message publish retries exhausted"
        description: "Pub/Sub publish operations failing after 3 retry attempts. Messages being routed to DLQ."
    ```

    Set `noDataState: OK` on all rules (quiet periods should not trigger alerts).
  </action>
