## What Was Built

### Backend (Task 1)

**Migration (`migrations/045_maintenance_windows.sql`):**
- `maintenance_windows` table with UUID PK, title (VARCHAR 200), description (TEXT), starts_at/ends_at (TIMESTAMPTZ), created_by, created_at
- Index on `ends_at` for efficient upcoming-window queries
- Table and column COMMENT annotations for clarity

**Models (`services/overlay-manager/models/maintenance.go`):**
- `MaintenanceWindow` struct with JSON tags matching API response
- `CreateMaintenanceRequest` with `binding:"required"` on title, starts_at, ends_at

**Repository (`services/overlay-manager/repository/maintenance_repo.go`):**
- `MaintenanceRepository` holding `*pgxpool.Pool`
- `Create` — INSERT RETURNING *
- `ListAll` — SELECT * ORDER BY starts_at ASC (admin view)
- `ListUpcoming` — SELECT * WHERE ends_at > NOW() ORDER BY starts_at ASC (user-facing)
- `Delete` — DELETE WHERE id = $1, returns error if not found

**Handler (`services/overlay-manager/handlers/maintenance.go`):**
- `HandleCreateMaintenance` — validates starts_at < ends_at, extracts user_id from JWT context, returns 201
- `HandleListMaintenance` — returns all windows, returns 200
- `HandleDeleteMaintenance` — deletes by /:id, returns 204
- `HandleListUpcoming` — non-admin upcoming endpoint, returns 200

**Wiring:**
- overlay-manager `cmd/main.go`: admin routes POST/GET/DELETE `/admin/maintenance`, protected route GET `/maintenance/upcoming`
- api-gateway `cmd/main.go`: proxy routes for all 4 endpoints under protectedAPI group
- api-gateway `models/service_config.go`: two ServiceConfig entries (`admin-maintenance`, `maintenance-upcoming`) pointing to overlayURL

### Frontend (Task 2)

**Types (`frontend/src/lib/types/maintenance.ts`):**
- `MaintenanceWindow` and `CreateMaintenanceRequest` interfaces

**API module (`frontend/src/lib/api/maintenance.ts`):**
- `maintenanceApi.list()`, `.create()`, `.remove()`, `.upcoming()`

**Admin page (`frontend/src/app/admin/maintenance/page.tsx`):**
- Auth guard redirects non-admins to /dashboard
- Lists all windows with active (amber) / upcoming (blue) badges and locale-formatted time ranges
- Create dialog with title, description, starts_at, ends_at (datetime-local) inputs
- Delete with window.confirm(), toast feedback on all actions
- Empty state with Wrench icon

**MaintenanceBanner (`frontend/src/components/MaintenanceBanner.tsx`):**
- Fetches from `maintenanceApi.upcoming()` on mount; errors suppressed (non-critical)
- Renders amber banner for active windows, blue for upcoming
- Per-window dismiss button using useState Set (session-only)
- Returns null when no visible windows

**Dashboard integration:**
- `MaintenanceBanner` added between AppNav and overlay grid with mb-4 wrapper
- AdminNav: Maintenance link added after Features
