User decisions from CONTEXT.md:
- Live streams only (no pre-recorded fixtures)
- Golden files captured from official youtube-listener (run and save output)
- Field-by-field semantic match (not byte-for-byte string comparison)
- Allow message_id differences (InnerTube vs official use different ID schemes)
- Allow timestamp differences within 1-second precision
- Test 100+ messages from 5-10 different streams (not 100 distinct streams)
- Git-style unified diff format for mismatches

Implement golden_capture.go as standalone CLI tool (package main) that:

1. **Configuration via flags:**
   - `-stream-url` (YouTube live stream URL, e.g., https://www.youtube.com/watch?v=VIDEO_ID)
   - `-duration` (capture duration, default 5m)
   - `-output-dir` (where to save golden files, default "./golden")
   - `-listener-binary` (path to official youtube-listener binary, default "../../../services/youtube-listener/youtube-listener")

2. **Capture workflow:**
   - Start official youtube-listener subprocess with minimal config (only Redis + stream URL)
   - Use exec.Command with Stdout piped to buffer
   - Parse listener's Redis Stream output (XREAD from chat:raw)
   - Connect to Redis (localhost:6379 by default, configurable via REDIS_HOST)
   - Read messages from chat:raw stream using XREADGROUP
   - Save each RawChatMessage as separate JSON file: `golden/{stream_name}_{message_type}_{sequence}.json`
   - Message types: text_message, super_chat, super_sticker, member_joined, member_milestone
   - Stop after duration expires or user Ctrl+C
   - Log progress: "Captured 15 messages (10 text, 3 super_chat, 2 member_joined)"

3. **Error handling:**
   - Verify youtube-listener binary exists before starting
   - Verify Redis connectivity before starting
   - Handle subprocess failures gracefully (log error, exit 1)
   - Cleanup subprocess on exit (defer cmd.Process.Kill())

4. **README.md instructions:**
   - Prerequisites: Built official youtube-listener binary, Redis running
   - Usage example: `go run golden_capture.go -stream-url https://www.youtube.com/watch?v=XXXXX -duration 10m`
   - Note: Requires YouTube live stream with active chat (find via /trending)
   - Recommendation: Capture from 5-10 different streams for variety (high-volume and low-volume)
   - Note: Run until you have 100+ golden files across different message types

**Why this approach:** User decision requires live streams only (no fixtures). Capturing from official listener ensures ground truth. Separate JSON files enable focused test cases per message type.

  </files>
  <action>
Create test/shared/ directory for shared test utilities.

Implement message_normalizer.go with:

1. **NormalizeMessage(msg *models.RawChatMessage) *models.RawChatMessage:**
   - Clone message (deep copy to avoid mutating original)
   - Apply normalization rules per user constraints:
     - Set MessageID = "<normalized>" (allow InnerTube and official to use different ID schemes)
     - Truncate Timestamp to 1-second precision (time.Truncate(time.Second))
     - Keep all other fields unchanged
   - Return normalized copy

2. **CompareMessages(official, innertube *models.RawChatMessage) (bool, string):**
   - Normalize both messages
   - Marshal to JSON with sorted keys (json.MarshalIndent)
   - Use nsf/jsondiff.Compare() for semantic comparison
   - If differences exist:
     - Generate git-style unified diff using jsondiff.CompareJSON with LeftJSON/RightJSON options
     - Return (false, diff_string)
   - If identical: return (true, "")

3. **Helper: AllowedFieldDifferences() []string:**
   - Return list of fields allowed to differ: ["message_id", "timestamp"]
   - Used for documentation and test assertions

4. **Unit tests (message_normalizer_test.go):**
   - TestNormalizeMessage_IDNormalization: Verify MessageID set to "<normalized>"
   - TestNormalizeMessage_TimestampTruncation: Verify microsecond precision removed
   - TestNormalizeMessage_OtherFieldsPreserved: Verify username, text, etc. unchanged
   - TestCompareMessages_Identical: Same message after normalization returns (true, "")
   - TestCompareMessages_DifferentContent: Different username returns (false, diff)
   - TestCompareMessages_AllowedDifferences: Different MessageID but same content returns (true, "")

**Why nsf/jsondiff:** Provides field-by-field comparison with human-readable diffs. Alternative go-cmp requires more manual configuration for struct comparison.
