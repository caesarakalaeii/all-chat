  <action>
Create discovery.go in innertube package with:

1. Discovery struct with http.Client and logger dependencies
2. DiscoverLiveStream(ctx, channelID) (videoID string, error) method that:
   - Fetches https://www.youtube.com/channel/{channelID}/live
   - Parses HTML using golang.org/x/net/html
   - Extracts canonical video ID from `<link rel="canonical" href="https://www.youtube.com/watch?v=VIDEO_ID">`
   - Checks `<meta property="og:video:type" content="live">` to filter premieres
   - Returns empty string + error if no live stream or premiere found
   - Logs discovery attempts with channel_id and video_id fields

3. Helper functions:
   - extractCanonicalVideoID(doc *html.Node) string - traverse DOM for canonical link
   - checkIsLiveMeta(doc *html.Node) bool - verify og:video:type is "live"

Create discovery_test.go with unit tests:
- TestDiscoverLiveStream_Success (mock HTTP response with live stream)
- TestDiscoverLiveStream_Premiere (mock response with premiere, expect error)
- TestDiscoverLiveStream_NoStream (mock response with no canonical link, expect error)
- TestDiscoverLiveStream_NetworkError (mock network failure, expect error)

Use HTML fixtures from research examples (canonical link pattern, og:video:type meta tag).

Why HTML parsing: User decision allows Claude's discretion. HTML parsing is simpler than InnerTube browse endpoint and sufficient for MVP. InnerTube browse can be added later as fallback if HTML parsing becomes unreliable.
