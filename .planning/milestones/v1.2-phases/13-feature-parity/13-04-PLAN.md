  <name>Modify AddDeletion to return immediate batch results</name>
  <files>services/youtube-listener-innertube/deletion/batch_detector.go</files>
  <action>
Change AddDeletion signature to return BatchResult immediately instead of returning nil while buffering.

Current behavior: AddDeletion returns nil, ticker goroutine processes windows after 100ms.
New behavior: AddDeletion checks if adding this deletion crosses the threshold, returns BatchResult immediately if batch detected.

Implementation:
1. Keep existing window tracking and ticker goroutine (for cleanup and final processing)
2. In AddDeletion, after appending deletion to window.deletions:
   - Check if len(window.deletions) >= d.threshold
   - If yes, synthesize BatchResult with IsBatch=true, Count=len, Reason=classifyReason(len)
   - Return the BatchResult
3. Return nil BatchResult if below threshold (not a batch yet)
4. Ticker goroutine continues to exist for window cleanup and edge cases

This allows parser to react immediately when batch is detected, without waiting for 100ms ticker.

Why this approach: Parser already has all the context needed to emit batch events (channelID, timestamp, streamID). Ticker-based emission would require passing publisher deep into batch_detector, creating circular dependencies. Parser-based emission is cleaner and leverages existing emission infrastructure.
