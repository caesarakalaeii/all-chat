Create cycles/detector.go implementing DFS cycle detection algorithm per RESEARCH.md Pattern 3:

**CycleDetector struct:**
- Field: repo *repository.ShareRepository (for querying accepted shares)
- Constructor: NewCycleDetector(repo *repository.ShareRepository) *CycleDetector

**HasCycle method signature:** `func (d *CycleDetector) HasCycle(ctx context.Context, fromUserID, toUserID string) (bool, error)`

**DFS algorithm:**
1. Create visited map[string]bool and recStack map[string]bool
2. Start DFS from fromUserID with target toUserID
3. In DFS function:
   - Mark current as visited and add to recursion stack
   - If current == target AND target in recStack → return true (cycle detected)
   - Query GetAcceptedSharesByRecipient(current) to get outgoing shares
   - For each share.SenderUserID:
     - If not visited: recurse with DFS
     - If in recStack: return true (back edge = cycle)
   - Remove current from recStack before returning
4. Return false if no cycle found

**Add repository method:** GetAcceptedSharesByRecipient(ctx, userID) returning accepted shares where recipient_user_id = userID. This represents "who does this user share TO" (outgoing edges in share graph).

**Comprehensive test coverage** (detector_test.go):
- No shares: fresh acceptance should succeed
- Direct cycle: A→B exists, B→A blocked
- 3-hop cycle: A→B→C exists, C→A blocked
- Valid chain: A→B→C exists, D→E succeeds
- Self-loop prevention (should never happen due to validation, but test handles gracefully)
- Disconnected components: multiple independent share chains

Use table-driven tests with setup helper creating test shares in temporary map (or use testcontainers for real DB).

type AcceptShareRequest struct {
    RecipientOverlayID string `json:"recipient_overlay_id" binding:"required"`
    ExpiryOption       string `json:"expiry_option" binding:"required"` // "this_stream", "custom", "unlimited"
    ExpiryHours        *int   `json:"expiry_hours,omitempty"`           // Required if expiry_option = "custom"

**Handler logic:**
1. Parse shareID from URL params
2. Get userID from JWT context (c.GetString("user_id"))
3. Bind and validate JSON body
4. If expiryOption == "custom": validate 1 ≤ expiryHours ≤ 168, return 400 if invalid
5. Start database transaction with h.db.Begin(ctx)
6. Get share request with SELECT FOR UPDATE (prevents race condition)
7. Verify share.RecipientUserID == userID (403 if not)
8. Verify share.Status == StatusPending (409 if not)
9. Call cycleDetector.HasCycle(ctx, share.SenderUserID, share.RecipientUserID)
10. If cycle detected: return 409 with user-friendly message from CONTEXT.md
11. Update share status to "accepted", set responded_at = NOW()
12. Commit transaction
13. Return 200 with updated share + sender_overlay_id for add-source prompt
