  <name>Task 1: Extend FindOverlaysForMessage with SQL UNION for shared overlay fan-out</name>
  <files>services/message-processor/router/overlay_router.go</files>
  <behavior>
    - Direct platform source lookup: platform=$1, channel_id=$2, is_active=true → returns direct recipient overlays (unchanged behavior)
    - Shared fan-out: finds recipient overlays that have ocs.platform='shared_overlay' AND ocs.is_active=true AND ocs.channel_id IN (sender overlay IDs that match platform=$1, channel_id=$2 with is_active=true)
    - UNION (not UNION ALL): deduplicates rows where same overlay appears in both branches
    - Revoked/expired shares excluded: UNION branch JOINs share_requests on status='accepted' only
    - Parameters $1 and $2 reused across both UNION branches (pgx reuses same bound values)
  </behavior>
  <action>
    Replace the query string in FindOverlaysForMessage with the UNION version. Keep the scan loop and all surrounding code unchanged — only the query string changes.

    Use this SQL (optimize as needed for index coverage):

    ```sql
    -- Direct platform sources (existing, unchanged behavior)
    SELECT DISTINCT o.id, o.user_id
    FROM overlays o
    JOIN overlay_chat_sources ocs ON o.id = ocs.overlay_id
    WHERE o.is_active = true
      AND ocs.is_active = true
      AND ocs.platform = $1
      AND ocs.channel_id = $2

    UNION

    -- Shared overlay fan-out: recipient overlays that subscribed to sender overlay
    SELECT DISTINCT o.id, o.user_id
    FROM overlays o
    JOIN overlay_chat_sources ocs
        ON o.id = ocs.overlay_id
        AND ocs.platform = 'shared_overlay'
        AND ocs.is_active = true
    JOIN share_requests sr
        ON sr.sender_overlay_id = ocs.channel_id
        AND sr.status = 'accepted'
    WHERE o.is_active = true
      AND sr.sender_overlay_id IN (
          SELECT o2.id
          FROM overlays o2
          JOIN overlay_chat_sources ocs2 ON o2.id = ocs2.overlay_id
          WHERE o2.is_active = true
            AND ocs2.is_active = true
            AND ocs2.platform = $1
            AND ocs2.channel_id = $2
      )
    ```

    Note: The existing query did NOT filter `ocs.is_active = true` in the first branch. Add this filter to the first branch for consistency with the UNION branch. This is a safe addition — sources with is_active=false should not receive messages.

    Note on parameters: $1=platform, $2=channelID — these same values are reused in the UNION subquery. pgx binds parameters by index across the entire query string; no new parameters needed.

    Do NOT change the Repository struct, NewRepository, Router struct, NewRouter, or Route method signatures.
  </action>
