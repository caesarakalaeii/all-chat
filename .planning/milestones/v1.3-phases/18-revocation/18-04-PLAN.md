<task type="auto">
  <name>Task 2: share_revoked WebSocket handler in overlay editor</name>
  <files>frontend/src/app/overlays/[id]/page.tsx</files>
  <action>
Add a WebSocket connection to the overlay editor page that listens for `share_revoked` events and notifies User B in real time.

The overlay editor already has `token` and `id` available. Add a new `useEffect` that:

1. Opens a WS connection to `/ws/overlay/{id}?token={token}` (same endpoint as preview page) — this registers User B's connection with the API Gateway's WS manager, which routes `share_revoked` events to all connections for that user.

2. Handles `share_revoked` in `onmessage`:
   ```typescript
   useEffect(() => {
     if (!token || !id) return;

     const protocol = window.location.protocol === 'https:' ? 'wss:' : 'ws:';
     const wsUrl = `${protocol}//${window.location.host}/ws/overlay/${id}?token=${token}`;
     const ws = new WebSocket(wsUrl);

     ws.onmessage = (event) => {
       try {
         const envelope = JSON.parse(event.data);
         if (envelope.type === 'share_revoked') {
           const revokerUsername = envelope.data?.revoked_by_username || 'someone';
           setNotification({
             type: 'error',
             message: `Your share with ${revokerUsername} was revoked`
           });
           setTimeout(() => setNotification(null), 5000);
           // Refresh sources so revoked rows grey out immediately
           overlaysApi.getSources(id).then(setSources).catch(console.error);
         }
         // Ignore chat_message and other overlay events — this WS is for notifications only
       } catch {
         // Ignore parse errors
       }
     };

     ws.onerror = () => {
       // Non-fatal: notification WS failure does not break the editor
       console.warn('[OverlayEditor] Notification WS error');
     };

     return () => {
       if (ws.readyState === WebSocket.OPEN || ws.readyState === WebSocket.CONNECTING) {
         ws.close();
       }
     };
   }, [id, token]);
   ```

Note: This WS connection is solely for receiving user-level notifications in the editor. It does not affect chat message handling. Add `useRef` for the WS only if needed to prevent double-connect in StrictMode — a simple dependency array `[id, token]` is sufficient for cleanup.
