# Frontend i18n

All-Chat's UI strings live in a typed catalog at `frontend/src/lib/i18n/`.
English is the only supported locale. There is no second catalog, no language
switcher, and no locale in the URL.

The design and the alternatives that were rejected are in
[ADR-0055](../adr/0055-ui-string-catalog-without-locale-routing.md). This guide is
the practical part.

## The module

| File | Holds |
|---|---|
| `config.ts` | `SUPPORTED_LOCALES`, `Locale`, `DEFAULT_LOCALE`, `isSupportedLocale` |
| `messages/en.ts` | the English catalog, a nested object literal ending in `as const` |
| `translate.ts` | `translate(messages, key, params?)`, `MessageKey`, `TFunction` |
| `format.ts` | `formatNumber`, `formatDateTime` |
| `index.ts` | `getTranslations`, `useTranslations` — the only entry points call sites import |

It is a pure module: no React Context, no store, no request state, no dependency.

## Adding a string

1. Add the key to `frontend/src/lib/i18n/messages/en.ts`, under the namespace for
   the surface that renders it.
2. Read it at the call site.

**Server Components, plain modules and tests** use `getTranslations()`:

```tsx
import { getTranslations } from '@/lib/i18n'

export default function Page() {
  const t = getTranslations()
  return <h1>{t('a11y.skipToMainContent')}</h1>
}
```

**Client Components** use `useTranslations()`:

```tsx
'use client'
import { useTranslations } from '@/lib/i18n'

export function Banner({ title }: { title: string }) {
  const t = useTranslations()
  return <button aria-label={t('maintenanceBanner.dismissLabel', { title })}>…</button>
}
```

Both return the identical `TFunction`, so a call site does not change when a
second locale lands.

`t()` takes a dotted key, checked at compile time. A key that is not in the
catalog is a type error, so `npx tsc --noEmit` catches a typo before any test
runs.

## Namespace convention

- camelCase, nested **at most three levels**: `maintenanceBanner.dismissLabel`,
  not `components.banners.maintenance.dismiss.label`.
- Keyed by **surface**, not by component internals — the namespace names the
  screen or widget a reader can point at.
- `common.*` is for a string genuinely shared by two or more surfaces. Do not
  create it, or any other namespace, to hold a single key nobody else reads.
- The whole object ends in `as const`. This is load bearing: `MessageKey` is
  derived from the literal key types, and widening the object silently turns the
  compile-time key check into `string`.

## Placeholders

Single braces, `{name}`, matching the convention already used in
`frontend/src/lib/errorMessages.ts`. Do not introduce a second syntax.

```ts
dismissLabel: 'Dismiss maintenance banner: {title}',
```

```ts
t('maintenanceBanner.dismissLabel', { title: 'Database upgrade' })
```

`params` is `Record<string, string | number>`. Every occurrence of a placeholder
is replaced, so `'{word} and {word}'` with `{ word: 'echo' }` gives
`'echo and echo'`.

There are no ICU plurals and no `select`. With one locale they buy nothing. When
plural rules are genuinely needed they go behind the same `t()` signature, so the
engine can be swapped without touching call sites.

**Do not concatenate translated fragments to build a sentence.** Word order is
the first thing a second language changes. Put the whole sentence in one key with
placeholders in it.

## Lookup never throws

An unknown key resolves to the key string. A missing param leaves the
`{placeholder}` visible. Both `console.warn` outside production.

That is deliberate, and it is the one rule not to "improve". Overlay pages render
inside OBS browser sources on live broadcasts. An exception raised from a string
lookup unmounts the tree, and the viewer sees a black overlay for the rest of the
stream. A visible key is obviously a bug and costs nobody their broadcast.

## Dates and numbers

Use `formatDateTime` and `formatNumber` from `@/lib/i18n` rather than
`toLocaleString()` or a bare `Intl` constructor.

```ts
import { formatDateTime } from '@/lib/i18n'

const DATE_OPTIONS: Intl.DateTimeFormatOptions = { month: 'short', day: 'numeric' }
formatDateTime(new Date(window.ends_at), DATE_OPTIONS)
```

Passing `undefined` as the locale — which is what `toLocaleString()` and
`new Intl.DateTimeFormat(undefined, …)` do — means "whatever locale the browser or
OBS instance happens to have". That made English copy render German month
abbreviations, and made the same banner read differently on two machines. These
wrappers default to the UI locale instead.

Both wrappers cache their `Intl` constructors, keyed by locale plus the serialised
options, so calling them per render is fine and you do not need a module-level
formatter constant.

Most of the frontend has **not** been migrated onto these yet: at the time of
writing there are still dozens of unpinned `toLocaleString()` / `Intl.*` call
sites. Each needs its own look at whether the value is UI copy or viewer data, so
they move over case by case rather than in a sweep.

## Why there is no provider

`useTranslations()` is hook-shaped but is not backed by a React Context.

- The frontend has **no React Context at all** —
  `grep -rn 'createContext\|useContext' frontend/src` returns nothing. State is
  Zustand or module singletons.
- Storybook renders components standalone, and `npx vitest --project storybook
  --run` is a required CI gate. A component that needs a wrapping provider to
  render would break it.

The hook exists purely as the seam, so adding a locale is a change inside
`src/lib/i18n/` rather than a sweep across every component.

## Why locale is not in the URL

`/overlay/[id]` is pasted into OBS browser sources, shared links, the browser
extension and the Stream Deck plugins, and left there for months. A
`/[locale]/overlay/[id]` segment would invalidate every overlay that already
exists, silently and mid-broadcast. Public routes are also indexed unprefixed via
`src/app/sitemap.ts` and `src/app/robots.ts`.

This is a rule, not a current limitation: **locale never goes in the URL.**

## What is not here

- Any second locale, translated copy, or language switcher.
- Locale selection at request time — no `middleware.ts`, no `cookies()` or
  `headers()` read, no `Accept-Language` parsing, no account preference, no
  locale column. Reading request state in the root layout makes every page
  dynamic, including the static marketing and docs pages, and with one locale the
  answer never varies.
- `next-intl`, `react-intl`, `i18next`. See ADR-0055.
- `errorMessages.ts`. It is a `Record<ChatErrorType, …>` with `actionableSteps`
  arrays and gets its own migration.
- Overlay chat message and event rendering. Viewer-authored chat content is never
  translated.

## Adding locale #2

In rough order:

1. Decide how the locale is chosen, and what it costs. This is the real work, and
   it is a decision that needs its own ADR: any request-time read (cookie,
   `Accept-Language`) opts every page out of static rendering. A build-time or
   per-user-fetch mechanism may be the better trade. Whatever is chosen, it must
   not put the locale in the path.
2. Add the code to `SUPPORTED_LOCALES` in `config.ts`.
3. Add `messages/<code>.ts`. Keep the shape identical to `en.ts`; type it as the
   English catalog's type so a missing or extra key is a compile error.
4. Map locale to catalog in `index.ts` — the only place that knows the mapping.
   `getTranslations` already takes a `Locale`.
5. Make `useTranslations()` read the resolved locale rather than
   `DEFAULT_LOCALE`, still without a provider.
6. Set the `lang` attribute in `src/app/layout.tsx` from the resolved locale
   instead of `DEFAULT_LOCALE`.
7. Migrate the strings the new locale actually needs. Every literal still at its
   render site is a string that silently stays English.
8. Cover the release steps in CLAUDE.md's "Shipping a Feature" — premium gate,
   onboarding tour entry, Patreon post. The foundation skipped them because it
   shipped nothing user-visible; a language is user-visible.

## Testing

Tests live in `frontend/src/lib/i18n/__tests__/`. Run them with:

```bash
cd frontend && npx vitest --project unit --run src/lib/i18n/
```

Never `npm test` in `frontend/` — it maps to bare `vitest`, which is watch mode.

Unit tests are only discovered under a `__tests__` directory; a test file
anywhere else is silently never run. The `unit` project is `environment: 'node'`,
so a component test needs a `// @vitest-environment jsdom` docblock — see
`frontend/src/components/__tests__/MaintenanceBanner.test.tsx`.

The `@ts-expect-error` line in `__tests__/translate.test.ts` is a gate, not a
comment: `tsconfig.json` type checks test files, so if `MessageKey` degrades to
`string` the suppression becomes unused and `tsc --noEmit` fails. Do not delete
it.

Every new file under `src/lib/i18n/` needs the AGPL header block. Nothing lints
for it.
