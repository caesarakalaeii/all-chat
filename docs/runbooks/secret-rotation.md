# Secret rotation

Rotate TOKEN_ENCRYPTION_KEY_V<n> (stored OAuth tokens), JWT_SECRET_V<n> (user/viewer JWTs) and SERVICE_JWT_SECRET_V<n> (service-to-service JWTs). For the DB password see `db-password-rotation.md`.

Targets the deployment repo (ArgoCD-managed manifests), context for the allchat cluster. The sweeper is `key-rotator`, built from `services/auth-service` (shared/encryption/versioned.go, shared/auth KeyChain) and run as CronJob `key-rotator-weekly` (Sunday 03:00 UTC).

## Hazards — read first

1. **Never `sops set`/`sops edit`/`sops updatekeys` on `allchat-secret.enc.yaml`.** The live Secret `allchat-secrets` has more keys than the SOPS snapshot; an sops write silently deletes the keys that exist only live, including rotation keys. Every secret mutation here uses `kubectl patch`.
2. **Never inspect secrets with `-o yaml`/`-o json`.** The output is recorded in `last-applied-configuration` and visible via `kubectl describe`. Keys only:
   ```bash
   kubectl --context default get secret allchat-secrets -n allchat \
     -o jsonpath='{.data}' | jq 'keys'
   ```
3. **JWT TTL windows.** User JWT TTL is 24h (`JWT_EXPIRY_HOURS` in `allchat-config`), service JWT TTL is 15 minutes. The old kid must stay valid until every token issued under it has expired.
4. **Per-overlay TTS signing secrets (`overlay_tts_configs.tts_signing_secret`) are not covered by this runbook.** Those are regenerated by the streamer in the overlay-manager TTS settings flow.

## Pre-flight

```bash
kubectl config current-context

# key names only, no values
kubectl --context default get secret allchat-secrets -n allchat -o jsonpath='{.data}' | jq 'keys'

kubectl --context default get pods -n allchat -l '!job-name'   # all Running, restarts stable
kubectl --context default get cronjob/key-rotator-weekly -n allchat
kubectl --context default get jobs -n allchat -l app=key-rotator   # no stuck/failed jobs

# current active kid(s)
kubectl --context default get deploy auth-service -n allchat \
  -o jsonpath='{range .spec.template.spec.containers[?(@.name=="auth-service")].env[*]}{.name}{"\n"}{end}' \
  | grep -E 'TOKEN_ENCRYPTION_KEY_V|JWT_SECRET_V' | sort
```

## Section 1: TOKEN_ENCRYPTION_KEY

Encrypts OAuth tokens in `users`, `viewer_sessions`, `youtube_oauth_tokens`, `kick_oauth_tokens` (ciphertext: `base64(kid | nonce | ct | tag)`).

Consumers mounting both `TOKEN_ENCRYPTION_KEY` era keys: `auth-service`, `overlay-manager`, `token-refresh-service`, `twitch-eventsub-listener`, `kick-listener`, `youtube-listener-innertube` (only when subscriber alerts are on), `discord-listener` (relay webhooks, ADR-0091; re-encrypts them itself on every relay sync), plus the `key-rotator` Job/CronJob.

### Steps

1. Determine the current latest kid (from pre-flight), set `CURRENT_VERSION`, `NEXT_VERSION=$CURRENT+1`, `SECRET_KEY_NAME="token-encryption-key-v${NEXT_VERSION}"`.
2. Generate the key and save it **before proceeding**; a lost key makes every row encrypted under it unrecoverable:
   ```bash
   NEW_KEY=$(head -c 32 /dev/urandom | base64)
   ```
3. Add to the secret:
   ```bash
   ENCODED=$(printf '%s' "$NEW_KEY" | base64)
   kubectl --context default patch secret allchat-secrets -n allchat \
     --type='json' \
     -p="[{\"op\": \"add\", \"path\": \"/data/${SECRET_KEY_NAME}\", \"value\": \"${ENCODED}\"}]"
   ```
4. Add a `TOKEN_ENCRYPTION_KEY_V<n+1>` secretKeyRef block to every consumer deployment in the deployment repo (same shape as the existing `_V1` entries), commit, let ArgoCD sync, confirm rollouts:
   ```bash
   for d in auth-service overlay-manager token-refresh-service twitch-eventsub-listener kick-listener; do
     kubectl --context default rollout status deployment/$d -n allchat --timeout=5m
   done
   ```
   New writes now use the new kid; old rows still decrypt through the multi-key chain.
5. Re-encrypt with the sweeper. Dry run first; review the counts; then run live (off-peak):
   ```bash
   kubectl --context default create job key-rotator-dryrun-$(date +%s) \
     --from=cronjob/key-rotator-weekly -n allchat \
     -- /app/key-rotator --dry-run --batch-size=100 --batch-delay-ms=50

   kubectl --context default logs -n allchat -l app=key-rotator --tail=500 \
     | jq 'select(.msg=="table sweep complete")'

   kubectl --context default create job key-rotator-rotate-$(date +%s) \
     --from=cronjob/key-rotator-weekly -n allchat
   kubectl --context default wait --for=condition=complete job -l app=key-rotator -n allchat --timeout=60m
   ```
6. Once a second dry run reports 0 re-encryptions, retire the old kid: remove its env blocks from the deployments and the key from the secret, then restart the consumers:
   ```bash
   kubectl --context default patch secret allchat-secrets -n allchat \
     --type='json' \
     -p="[{\"op\": \"remove\", \"path\": \"/data/<old-key-name>\"}]"
   ```

### Rollback

`decrypt: cipher: message authentication failed` or `token decryption failed` in logs means decryption is broken: revert the deployment manifest commit; the old key stays in the secret until step 6 runs, so the revert is always valid before that.

## Section 2: JWT_SECRET

Signs user/viewer JWTs. Consumers (issuer and/or validator): `auth-service`, `api-gateway`, `overlay-manager`, `share-service`.

1. Determine the current kid (pre-flight).
2. Generate:
   ```bash
   NEW_JWT_SECRET=$(head -c 32 /dev/urandom | base64)
   ENCODED=$(printf '%s' "$NEW_JWT_SECRET" | base64)
   ```
3. Patch it into the secret with the same JSON-patch shape as Section 1 step 3 (`jwt-secret-v<n+1>`).
4. Add the `JWT_SECRET_V<n+1>` env block to the four consumer deployments, commit, ArgoCD sync, confirm rollouts.
5. Verify the issuer switched: sample a fresh token, decode its header (`cut -d. -f1 | base64 -d | jq .kid`), expect `v<n+1>`.
6. **Wait T+24h** (active sessions hold tokens issued under the old kid), then remove the `_V<n>` env blocks and the secret key. The legacy kid-less `JWT_SECRET` stays until the second rotation.

### Rollback

401s with `invalid or expired token` after the deploy, `auth.ValidateJWTWithKeyChain` failures in api-gateway logs: revert the manifest commit; the old key remains in the secret until step 6.

## Section 3: SERVICE_JWT_SECRET

Signs service-to-service JWTs (TTL 15 min). Consumers: `source-manager`, `api-gateway`, `share-service`, `twitch-eventsub-listener`, `twitch-listener`, `kick-listener`, `tiktok-listener`, `youtube-listener-innertube`, `discord-listener` (the latter two also via the legacy `SOURCE_MANAGER_SECRET` alias to the same secret key).

Same six steps as Section 2, substituting the names, with two differences: nine consumer deployments instead of four, and the retirement wait is **T+15 min** instead of T+24h.

### Rollback

Listeners get 401 on `/internal/*` routes; source-manager rejects service tokens; share-link generation fails. Revert the manifest commit; validate by checking a listener can reach source-manager (images are distroless, ADR-0092, so use a debug container):

```bash
POD=$(kubectl --context default get pods -n allchat -l app=twitch-listener -o jsonpath='{.items[0].metadata.name}')
kubectl --context default debug -n allchat "$POD" -i --image=busybox:1.37 --profile=restricted -- \
  wget -qO- http://source-manager:8088/health/ready
```

## Sweeper operations

Flags: `--dry-run` (counts only, no DB writes), `--batch-size` (default 200), `--batch-delay-ms` (default 25), `--skip-table=<table>` (repeatable).

Telemetry per table: `{"msg":"table sweep complete","table":...,"rows_scanned":...,"rows_re_encrypted":...,"errors":...,"current_kid":...}`.

- **TikTok rows are intentionally skipped**: migration 051 sets `encryption_version=0` on `tiktok_oauth_tokens` and the sweeper filters `WHERE encryption_version >= 1`; the Node.js listener expects plaintext.
- A legacy ciphertext whose first byte coincidentally matches a registered kid logs `decrypt: cipher: message authentication failed` and then falls back to the legacy key: expected, recoverable, counted in errors.
- `overlay_tts_configs.encrypted_api_key` is BYTEA; if you change the sweeper binary, re-run `TestSweeper_TTSBytea`.

`services/auth-service/cmd/token-encryption-backfill` is a separate one-time tool, not a rotation tool: it encrypts legacy plaintext token rows to the current format. It is idempotent (rows that already decrypt are skipped) and scoped with `--skip-users` / `--skip-youtube` (plus `--dry-run`); verify the flags against its `main.go` before running. Key rotation itself is always the key-rotator sweeper above.

## Post-rotation bookkeeping

The new secret values exist only in the live K8s Secret, not in the SOPS source; record the drift in the secrets drift register. Reconciling that drift is a separate queued task; until it lands, `kubectl patch` remains the only safe mutation path for `allchat-secrets`.
